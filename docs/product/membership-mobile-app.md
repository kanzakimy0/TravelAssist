# TravelAssist Free / Premium 与手机 App 会员设计

> 状态：v1.0 / 已确认设计  
> 日期：2026-09-05  
> 适用范围：Web 账号体系、未来 iOS / Android App、AI 用量控制、行程共享、离线、实时旅行助手、翻译沟通。

## 1. 商业定位

TravelAssist 采用两条互补收入线：

```text
Premium 月会员订阅收入
+
Partner / Affiliate 预订返佣
```

因此会员设计必须避免阻断酒店、景点门票、餐饮、交通、租车、eSIM、机场接送等预订流程。

核心原则：

> **只限制高成本 AI / 自动化能力，不限制旅行执行和 Partner 交易。**

> **Free 能正常完成旅行；Premium 负责主动管理旅行。**

---

## 2. 当前会员等级

当前阶段只设计两档：

```text
Free
Premium 月会员
```

暂不冻结：

- 年会员
- Family 独立套餐
- Student 套餐
- Trip Pass

Premium 权益绑定用户账号 `user_id`，不绑定单一设备。Web 购买后 App 可识别，App 购买后 Web 也应同步会员状态。

---

## 3. Free 免费账号定位

Free 的目标不是做一个残缺产品，而是：

> **能够规划、查看、预订、导航并正常完成一趟旅行。**

Free 保留：

- 已生成行程查看
- 我的旅行
- 地图
- 当前定位
- 每日时间轴
- 今日 / 下一站基础信息
- 基础导航入口
- 基础天气
- 基础行程编辑
- Reservation Hub 基础订单查看
- 查看本人 Confirmation / Voucher / QR Code
- 查看取消规则与 Partner 管理入口
- 酒店搜索、比价、预订
- 景点 / 门票搜索与预订
- 餐厅预约
- 火车 / 巴士 / 交通购票
- 租车
- eSIM
- 机场接送
- 所有 Partner 核心预订入口

以上核心交易功能不得进入 Premium 会员墙。

---

## 4. Free 每日 AI 使用额度

为了控制模型、地图 / 路线、翻译和第三方 API 成本，Free 对高成本 AI 操作采用每日 Credits。

第一版冻结：

> **Free 每天 10 AI Credits。**

建议消耗：

| 操作 | Credits |
|---|---:|
| 普通 AI 问答 | 1 |
| 翻译一段文字 | 1 |
| 小范围修改一个景点 / 餐厅 / 节点 | 1 |
| 单日重新规划 | 2 |
| 完整行程重新生成 | 4 |

每日额度按用户本地日期恢复。具体刷新实现应统一使用账号时区规则，避免跨设备重复刷新。

### 4.1 不消耗 Credits

以下操作不计 AI Credits：

- 查看已有行程
- 查看地图
- 当前定位
- 查看每日时间轴
- 打开基础导航
- 查看酒店 / 景点 / 餐厅
- Partner 比价与预订
- Reservation Hub
- 查看本人 Voucher / QR / Confirmation
- 查看取消规则
- 基础天气
- 严重灾害 / 交通停运 / 紧急安全提醒

原则：

> **限制计算，不限制交易，不限制用户访问自己已经购买的旅行资料。**

### 4.2 额度用完状态

Free 当日额度用完后，页面应明确说明 AI 暂时不可继续使用，但旅行本身仍然可正常执行：

```text
今日 AI 使用额度已用完

您仍然可以：
✓ 查看行程
✓ 使用地图与基础导航
✓ 查看订单、门票与 QR
✓ 预订酒店 / 景点 / 餐厅 / 交通

AI 使用额度将在下一次日额度恢复时重新可用。

[升级 Premium]
```

不得做成“额度用完以后无法继续旅行”的阻断体验。

---

## 5. Premium 月会员定位

Premium 的核心定位：

> **TravelAssist 不只帮用户计划旅行，而是在旅行开始后持续跟随变化、判断影响，并协助调整。**

Premium 不建议对外宣传“无限 AI”。正式产品文案采用：

- 高额度 AI
- 合理使用范围

后台保留 Fair Use / Abuse Protection 限流，避免极端使用导致不可控成本。

---

## 6. Premium 核心能力：行程导入 / 导出

### 6.1 导入别人分享的行程

Premium 可以把他人主动分享给自己的行程导入为正式 Trip。

允许来源可逐步支持：

- TravelAssist 分享链接
- TravelAssist 行程文件
- 结构化导入格式
- 后续支持的其他合法导入方式

导入后可选择：

```text
原样导入
按我的偏好优化
只导入景点
只导入路线
```

不得允许用户读取未被分享 / 未授权的私人行程。

### 6.2 导出自己的行程

Premium 可导出完整旅行包，格式可逐步支持：

- PDF
- Calendar / ICS
- 每日时间轴
- 地址清单
- 酒店 / 景点 / 餐厅 / 交通摘要
- TravelAssist 结构化行程格式

订单凭证、QR、个人信息等敏感数据默认不应因为普通“分享行程”自动暴露；需要独立的受控导出 / 分享权限。

---

## 7. Premium 完整离线旅行

Premium 支持完整旅行离线包。

至少包括：

- 全部行程
- 每日时间轴
- 关键地图基础数据
- 酒店地址
- 景点地址
- 餐厅地址
- 交通摘要
- 用户已有 Voucher / QR Code 的安全离线副本
- 订单号 / Confirmation
- 紧急联系方式
- 基础当地语言短语

Free 可以缓存当前页面或少量必要信息，但“完整整趟旅行离线包”属于 Premium。

手机 App 上应把离线状态、最后更新时间和数据有效性显示清楚。

---

## 8. Premium 同行席位与实时共享

每个 Premium 主账号包含：

> **1 个同行席位。**

主账号可邀请 1 个同行人的 TravelAssist 账号加入当前共享旅行。

同行人在该共享 Trip 中可以：

- 查看实时行程
- 查看地图和下一站
- 接收主账号确认后的行程修改
- 接收共享旅行提醒
- 查看被允许共享的共同订单信息
- 在 App 中实时获得最新版本行程

同行席位不等于赠送完整 Premium：

- 不允许同行人因此在自己的其他旅行中使用完整 Premium
- 不允许同行人继续邀请第三人
- 不自动获得独立高额度 AI
- Premium 权益只在被邀请的共享旅行范围内生效

## 9. Premium 手机 App：实时旅行判断

手机 App 是 Premium 价值最高的载体之一。

系统可以持续结合可用数据判断：

- 天气变化
- 强降雨 / 高温 / 暴雪等
- 公共交通晚点 / 停运
- 航班延误 / 取消
- 景点临时闭馆
- 营业时间变化
- 当前行程延误
- 用户晚出发
- 已有订单时间冲突
- 后续景点 / 餐厅 / 酒店受到的连锁影响

示例：

```text
14:10

检测到：
16:00 后强降雨

受影响：
16:30 伏见稻荷
18:00 鸭川散步

已确认：
19:30 餐厅预约不可移动
```

Premium AI 进一步计算：

```text
建议调整

14:30 京都国立博物馆
16:40 锦市场
19:30 保留原餐厅预约

伏见稻荷
→ 明日 08:30

预计减少雨中步行 4.2km

[采用调整]
```

---

## 10. 自动调整必须由主账号确认

AI 可以主动：

- 发现风险
- 判断影响
- 生成替代方案
- 计算后续连锁变化

但涉及已确认共享行程时，第一版默认不能静默自动改掉所有人的行程。

标准流程：

```text
检测异常
↓
AI 分析影响
↓
生成调整建议
↓
主账号确认
↓
正式更新 Trip
↓
地图 / 时间轴 / Reservation 状态同步
↓
同行人 App 实时同步
```

同行人收到：

```text
行程已更新

今天下午行程已调整
原：伏见稻荷
改：京都国立博物馆
原因：16:00 后强降雨

[查看新路线]
```

## 11. Free 与 Premium 的安全提醒边界

严重安全信息不能因为会员状态被隐藏。

Free：

- 显示台风 / 地震 / 极端天气
- 显示铁路完全停运
- 显示航班取消
- 显示景点紧急关闭等基础事实

Premium：

```text
基础事实提醒
+
判断影响哪些后续节点
+
查询 / 生成替代方案
+
重新计算路线
+
判断订单冲突
+
一键调整
+
同步同行人
```

因此 Premium 收费的是“主动分析与处理”，不是“安全信息本身”。

## 12. Premium 高级翻译与对外沟通

Premium 支持根据当前 Trip / Reservation 上下文生成适合酒店、餐厅、活动方等场景的当地语言沟通内容。

例如用户输入：

> 我们大概晚上 11 点才能到，可以保留房间吗？我们有一个 6 岁的孩子。

系统可结合：

- 酒店名称
- 用户姓名（经用户允许）
- 入住日期
- 订单号（经用户允许）
- 目的地语言
- 具体沟通场景

生成礼貌日语 / 英语等内容。

支持：

```text
[查看原文]
[日语]
[英语]
[复制]
[发送]
```

“发送”必须区分渠道能力：

### 支持 Partner Messaging / Email API / 官方通信接口

在取得用户授权和合作权限后，可由 TravelAssist 内完成发送。

### 不支持直接发送

TravelAssist 只能：

- 生成文本
- 复制文本
- 打开对应 Partner / 邮件 / 酒店消息入口
- 在技术允许时预填内容

不得在未实际发送成功时显示“已发送”。

## 13. Premium 与 Reservation Hub 的关系

所有用户免费：

- 通过 TravelAssist 发起 Partner 预订
- 查看自己的订单
- Voucher / QR / Confirmation
- 基础订单状态
- 取消政策
- Partner 管理入口
- 基础冲突提示

Premium 可增强：

- 确认邮件自动识别与整理
- 更高级的账号自动同步
- 自动订单冲突分析
- 行程改变后的订单影响判断
- 高级主动提醒
- 价格监控（后续）

会员墙不得阻断会产生 Affiliate / Partner 转化的核心流程。

## 16. 第一版 Premium 必须优先实现

按产品价值排序：

1. 行程导入 / 导出
2. 完整离线旅行包
3. 1 个同行席位 + 实时行程同步
4. 天气 / 交通 / 行程状态监控
5. 后续行程影响分析
6. 一键重排行程
7. 高级主动提醒
8. 高级酒店 / 餐厅等场景翻译与沟通

价格持续监控、多人更多席位、锁屏小组件、高级地图模式等可进入后续版本。

## 17. 已冻结规则

截至 2026-09-05：

- [x] 当前只设计 Free + Premium 月会员。
- [x] Free 每天 10 AI Credits。
- [x] AI Credits 只限制高成本计算，不限制预订交易。
- [x] 酒店、门票、餐厅、交通、租车、eSIM 等 Partner 预订对 Free 开放。
- [x] 用户始终可以查看自己的订单、Voucher、QR 和取消规则。
- [x] 严重安全提醒不进入会员墙。
- [x] Premium 采用高额度 / Fair Use，不宣传无限。
- [x] Premium 支持行程导入 / 导出。
- [x] Premium 支持完整离线旅行。
- [x] Premium 主账号包含 1 个同行席位。
- [x] Premium 共享旅行支持同行人 App 实时同步。
- [x] Premium 手机端负责天气、交通、闭馆、延误和后续影响判断。
- [x] AI 可主动建议调整，但共享行程默认由主账号确认后正式修改。
- [x] Premium 支持高级场景翻译与酒店 / 餐厅沟通。
- [x] 直接发送消息仅在渠道 API / Messaging 能力和用户授权允许时执行。

## 18. 仍待确定

- Premium 具体月费金额
- Premium 后台实际 Fair Use 数值

- 年费是否推出

Codex 不得自行把这些待定项实现成正式业务规则。

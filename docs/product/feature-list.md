## 6. 功能范围规则

- P0 目标是跑通“需求 → 多方案 → 地图行程 → 调整 → 保存”的核心闭环。
- P1 补齐“我的旅行 → Partner 预订 → Reservation Hub → 外部订单管理”的交易与管理闭环。
- P2 手机 App 重点解决“旅行当天执行”，Premium 重点解决“主动判断与管理旅行变化”。
- **Free 每天 10 AI Credits，只限制高成本 AI 计算。**
- **酒店、门票、餐厅、交通、租车、eSIM 等 Partner 核心预订对 Free 开放。**
- **用户自己的 Reservation / Voucher / QR 不得因为会员状态不可访问。**
- **严重安全信息不进入会员墙。**
- Premium 对外使用“高额度 / Fair Use”，不承诺无限 AI。
- Premium 共享旅行默认由主账号确认 AI 调整后再同步同行人。
- 任何功能进入开发前都应建立独立 GitHub Issue。
- 尚未确认的功能不能因为实现方便而默认进入正式范围。
- App 阶段优先复用业务层和数据层，不重复实现一套独立规则。

详细会员与 App 规则见 `docs/product/membership-mobile-app.md`。
详细外部订单规则见 `docs/ui/trip-external-reservations.md`。

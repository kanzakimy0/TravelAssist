# AI 行程生成与调整流程

> 状态：v0.1 / 产品流程已确定，模型与技术实现待定

## 1. AI 的定位

AI 不是单独的聊天机器人，而是 TravelAssist 的自然语言交互层。

它负责把用户语言转换为结构化旅行条件，并把行程系统的结果解释回用户。

```text
自然语言
   ↕
AI 解释 / 编排层
   ↕
结构化 Trip / Preference State
   ↕
路线、景点、交通、住宿、餐饮推荐系统
```

## 2. 首次生成流程

```text
用户进入首页
  ↓
让我们开始吧 / AI 对话
  ↓
用户描述目的地、日期、同行人、想做的事情
  ↓
AI 提取已知信息
  ↓
判断是否缺少生成行程所必需的条件
  ↓
需要时只追问关键缺口
  ↓
形成结构化旅行条件
  ↓
生成多套候选方案
  ↓
进入地图行程主页面
```

原则：

- 不要强迫用户先完成长表单。
- 用户已经在自然语言里提供的信息不要重复询问。
- 不重要的偏好可以先使用默认值，之后再调。
- 重要硬限制必须明确保存。

## 3. 多方案生成

系统应生成具有明显差异的候选方案，而不是同一路线的小幅换序。

每个方案至少包含：

- 方案名称
- 每日路线
- 景点 / 活动
- 交通段
- 午餐 / 晚餐区域
- 住宿区域
- 节奏与移动强度概要
- 推荐理由
- 主要取舍

推荐 1 作为当前主方案，其他方案保持精简，用户选中后再展开。

## 4. 修改流程

用户可以通过两条路径修改：

### A. 自然语言

例如：

- 第二天轻松一点。
- 不要坐公交。
- 我们带婴儿。
- 想多安排几个拍照地点。
- 把某个景点放到上午。

AI 应：

1. 判断修改意图。
2. 识别修改对象与作用范围。
3. 更新结构化状态。
4. 判断哪些行程段受到影响。
5. 只重新计算必要部分，或在必须时重算整个方案。
6. 更新地图、时间轴和右侧摘要。
7. 告诉用户主要变化与取舍。

### B. 结构化设置

用户在右侧设置面板修改同行人、交通或景点喜好后：

1. Preference State 更新。
2. AI 上下文读取最新状态。
3. 行程生成器重新评估。
4. 所有视图同步。

## 5. AI 不应做的事情

- 不得把未确认的产品规则当成永久业务规则。
- 不得在用户明确硬限制与系统默认值冲突时静默忽略用户。
- 不得只输出文字行程而不更新结构化 Trip State。
- 不得让聊天记录成为唯一的数据源。
- 不得重复询问系统已经保存且仍有效的信息。

## 6. 推荐解释

推荐结果应逐步支持解释：

- 为什么安排这个景点？
- 为什么建议住这个区域？
- 为什么这段使用电车而不是公交？
- 为什么删除 / 替换某个景点？
- 哪些偏好无法同时满足？

AI 解释应基于实际结构化结果，不应事后编造理由。

## 7. 冲突处理

当条件互相冲突时，例如：

```text
少步行
+ 不乘公共交通
+ 时间有限
+ 希望安排大量景点
```

系统应：

1. 检测冲突。
2. 说明无法全部满足的原因。
3. 给出 1~3 个可理解的取舍方向。
4. 若已有明确优先级，可自动选择并说明。
5. 若没有优先级且影响显著，再询问用户。

## 8. 上下文范围

AI 至少需要访问当前旅行的：

- 日期
- 目的地 / 起终点
- 同行人
- 偏好
- 硬限制
- 当前选中方案
- 每日行程
- 地图地点
- 交通段
- 推荐住宿 / 餐饮区域
- 用户刚刚进行的修改

长期用户资料与当前旅行资料需要区分。

## 9. 建议的数据流

```text
User Message
   ↓
Intent / Constraint Extraction
   ↓
Preference + Trip Patch
   ↓
Validation / Conflict Check
   ↓
Trip Planner / Recommender
   ↓
Trip State
   ├─ Map
   ├─ Timeline
   ├─ Recommendation Cards
   └─ AI Response
```

这里是产品级逻辑，不限定具体 AI SDK 或 Agent 框架。

## 10. 当前已冻结

- [x] AI 可从首页直接进入。
- [x] AI 在行程主页面持续可用。
- [x] 自然语言与结构化设置双向同步。
- [x] AI 负责提取需求、生成方案、调整方案和解释变化。
- [x] 系统应生成多个候选方案。
- [x] 不重复询问已经掌握的有效信息。
- [x] 结构化 Trip / Preference State 是事实源，不以聊天文本作为唯一事实源。

## 11. 未确定事项

- 使用单模型还是多模型路由。
- Agent / Tool Calling 的具体实现。
- 行程生成是一次完成还是分阶段规划。
- 模型选择与成本预算。
- 对话上下文压缩与持久化策略。
- 推荐解释的可追溯数据结构。
- 需要哪些外部搜索 / 地图 / 交通工具调用。
- 行程重算的增量算法。

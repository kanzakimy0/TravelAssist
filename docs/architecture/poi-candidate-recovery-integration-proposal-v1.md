# POI 候选恢复与正式接入提案 v1

状态：候选层已按用户授权执行；**正式导入仅为提案，未执行**。现有正式编号、Registry、冻结契约、产品代码、数据库及部署保持不变。

## 当前可继续的开发

Profile、Preference、Companion、Trip Library、Engine、UI 等现有模块继续使用其已验收数据与契约。离线候选资料与产品输入没有自动接线；本次缺失档案不要求重写这些模块。

候选加工继续使用现有 source IDs，允许补充有依据的字段，保留 provenance 与未知值。candidateKey 不能冒充正式 Master Code，名称范围化 anchor 也不能冒充 Route Provider ID。

## 正式接入前的门槛

1. 建立引用审计：逐项检查真实环境中 Trip、计划项、POI 引用及外部导出使用的编号，不修改这些环境。本次没有访问 Production/Staging DB，不能声称它们没有旧引用。
2. 冻结权威已知绑定：保留全部历史声明，2,979 条缺失映射与 175 个冲突进入不可覆盖清单。未知号位不能被当成空位；没有被证明未占用的范围不分配新号。
3. 对候选身份建立可验收的正式映射，每条映射明确来源、旧码、来源键、适用版本及冲突结论。无法证明的项继续隔离，不能按顺序重编。
4. 独立验收属性：当前 82 个值为编辑建议，非官方评分或 Human Gold。补齐身份来源、地区/类型覆盖以及需要的 Visit 数值后，重新执行受影响批次。分类或缺失不能转成 0/5。
5. 交通接入使用既有 7.5 Route contract；先核实 anchor 身份，再按现有事实新鲜度策略获取实际路线。当前名称候选、历史缓存与 2 条邻接不保证可达性。
6. 对导入清单做 dry-run、引用完整性和前后 diff；任何变更正式编号、兼容映射或产品接线另立任务，得到用户明确验收后才执行。

## 兼容与回退

导入前后保留不可变版本和 hash。已存在编号不变；兼容映射必须可追溯，禁止静默转向其他现实地点。若新属性被撤回，只撤回对应属性版本，不删除身份、不重置业务 revision、不覆盖 current Trip。需要数据库变更时另行评审新增 migration，本任务不创建 migration。

恢复资料是旁路补充，而不是失踪主表的替代权威。即使最后永远找不到原文件，也可以继续隔离、补证据与开发现有模块；完整历史 POI 的发布能力仍应明确显示“未认证”。

## 1. 页面定位

旅行偏好中心用于管理用户的**长期默认旅行偏好**。

它不是本次旅行的临时设置页，也不是一个铺满开关和滑轨的后台表单。

核心目标：

1. 让用户进入页面后能**一眼看懂自己的旅行偏好画像**。
2. 用自然语言解释画像，避免用户只看到图形却不理解含义。
3. 通过少量摘要卡进入详细偏好设置。
4. 保持与 Planner 偏好参数一致，避免 Personal Center 和 Planner 形成两套不同业务规则。
5. 长期偏好可被 Planner 新行程读取，但具体旅行中的临时调整不得反向覆盖长期偏好。

核心关系：

```text
Personal Center Preference
= 长期默认偏好

Planner Trip Preference
= 本次旅行临时偏好 / 条件

长期偏好 → 新旅行默认读取
本次旅行修改 → 只影响当前 Trip
```

## 2. 与 A 偏好系统的关系

现有业务偏好基准：

`docs/preferences/preference-system.md`

其核心结构保持不变：

```text
大项目
└─ 中项目（快速设置）
   └─ 小项目（详细设置）
```

WBS 1.25 只冻结**Personal Center 长期偏好的展示与导航方式**，不得重新创造一套与 A Planner 不兼容的偏好枚举。

### 2.1 Personal Center 不直接承载的项目

以下项目不作为 1.25 首页一级偏好卡：

- 同行人：由 WBS 1.26 独立管理。
- 日期 / 行程长度：属于具体 Trip，由 Planner 管理。
- 本次旅行临时限制：属于 Planner 临时设置。

### 2.2 共享原则

```text
B Preference UI / Persistence
        ↓
Preference Contract
        ↓
A Planner / Recommendation / AI
```

偏好画像是结构化偏好数据的可视化结果，**不是新的事实源**。

## 4. 双多边形偏好画像

偏好首页最核心的识别性组件为两个并排的六边形 Radar / Spider Chart。

用户第一眼先看“形状”，第二眼看“一句话解释”，需要修改时再进入详细设置。

### 4.1 画像一：景点偏好画像

回答问题：

> **您喜欢看什么、体验什么？**

冻结为 6 个维度：

```text
自然
历史
人文
艺术
摄影
活动体验
```

#### 维度语义

| 维度     | 代表内容                                     |
| -------- | -------------------------------------------- |
| 自然     | 山川、湖泊、海岸、公园、自然景观             |
| 历史     | 古迹、历史建筑、遗址、寺社、博物馆等历史内容 |
| 人文     | 街区、市场、当地生活、社区文化、传统生活方式 |
| 艺术     | 美术馆、设计、建筑、演出、艺术空间           |
| 摄影     | 取景价值、摄影体验、光线 / 景观导向活动      |
| 活动体验 | 手作、户外、节庆、娱乐、参与式体验           |

> “餐饮”不进入该六边形，继续作为独立偏好大类，避免将不同业务维度混入一个画像。

### 4.2 画像二：旅行风格画像

回答问题：

> **您喜欢怎样旅行？**

冻结为 6 个维度：

```text
轻松
经典
计划
探索
参与
深度
```

#### 维度语义

| 维度 | 代表倾向                          |
| ---- | --------------------------------- |
| 轻松 | 休息空间、较少赶路、较低连续强度  |
| 经典 | 对代表性 / 经典目的地和路线的偏好 |
| 计划 | 对明确行程结构、提前安排的偏好    |
| 探索 | 对小众、未知、非标准路线的接受度  |
| 参与 | 对互动、参与式体验的偏好          |
| 深度 | 对较长停留、深入理解当地的偏好    |

这些轴是独立画像维度，不要求互为绝对反义词。例如用户可以同时偏好“经典”和“探索”。

### 4.3 Radar 显示规则

- 六边形背景线使用极淡灰粉色。
- 用户画像线使用珊瑚朱红 / 樱粉系强调色。
- 填充透明度较低，不遮挡轴线。
- 普通视图不显示百分比。
- 普通视图不显示复杂评分公式。
- Hover / Focus 时显示语义级别，例如：`很喜欢 / 喜欢 / 一般 / 较少`。
- 内部数值如何归一化由 WBS 5.11 Preference Schema 冻结，1.25 不写死算法。
- Radar 是**摘要可视化**，不是独立数据存储。

### 4.4 Radar 交互

默认 Radar 为只读画像，不要求用户直接拖动节点。

点击 / 键盘激活维度后进入对应详细设置或聚焦相应分类：

- 景点画像维度 → `景点与活动` 对应细分项。
- 旅行风格维度 → 对应风格 / 高级偏好设置。

这样避免用户误以为拖动 Radar 就能覆盖所有底层详细偏好。

## 5. 画像解释区

两个 Radar 下方显示一条统一的自然语言总结：

```text
您的旅行画像
偏爱自然与历史景点，喜欢轻松、有计划、带一点探索感的旅行方式。
```

### 5.1 规则

- 只总结最显著的 2–4 个维度。
- 不堆叠全部偏好。
- 不显示算法分数。
- 文案应该自然、像旅行顾问，而不是数据报告。
- 用户修改偏好后，该总结应同步更新。

### 5.2 说明问号

可以在“旅行画像”标题附近放一个小型 `?`。

沿用项目全局规则：

- 问号视觉尺寸应比正文约小 20%。
- Hover / Focus 才显示说明。

说明内容：

> 画像根据您保存的长期偏好生成。具体旅行中的临时调整不会永久改变这里。

## 6. 六个详细偏好摘要卡

双画像负责“看懂自己”，摘要卡负责“进入修改”。

冻结为 6 个大类：

```text
移动
景点与活动
餐饮
住宿
预算
旅行体验
```

### 6.1 卡片共同规则

每张卡只显示：

- 一张写实主题照片
- 大类名称
- 当前最重要的 2–3 项摘要
- 已设置数量或状态
- `>` 进入详细设置

不在首页直接展开全部中 / 小项目。

### 6.2 移动

摘要示例：

```text
移动
铁路优先 · 少换乘 · 步行中等
```

点击后继续沿用 A 的三级结构：

```text
移动 / 交通
↓
中项目快速设置
↓
小项目详细限制
```

已讨论的详细方向包括少换乘、少步行、不乘公共交通、不乘公交、不乘游船等；最终业务枚举以共享 Preference Master Data 为准。

### 6.3 景点与活动

摘要示例：

```text
景点与活动
自然 · 历史 · 摄影
```

详细层覆盖：

- 景点类别
- 活动形式
- 行为目的
- 摄影等特定体验需求

具体 Master Data 不由 UI 自行扩充。

### 6.4 餐饮

摘要示例：

```text
餐饮
当地料理 · 小店 · 排队接受中等
```

详细层未来承载菜系、预算、用餐时间、排队容忍度、特殊饮食等。

### 6.5 住宿

摘要示例：

```text
住宿
交通方便 · 舒适 · 少换酒店
```

偏好最终应影响住宿区域、交通便利、换酒店次数、夜间活动便利和次日出发效率。

### 6.6 预算

摘要示例：

```text
预算
中等预算 · 更愿意花在住宿和体验
```

首页不要求显示精确总金额；具体旅行预算属于具体 Trip。

长期预算偏好主要表达：

- 总体消费倾向
- 更愿意把预算分配在哪些方面

### 6.7 旅行体验

摘要示例：

```text
旅行体验
摄影 · 当地文化 · 日落夜景
```

用于承载不完全属于交通 / 住宿 / 餐饮，但明显影响行程生成的体验偏好。

## 7. 更多详细设置

六张主要卡下方保留：

`更多详细设置 >`

用于承载低频、高级、跨分类偏好。

方向可包括：

- 每日较早 / 较晚活动接受度
- 连续游览强度
- 休息需求
- 排队容忍度
- 天气敏感度
- 行李情况下的移动偏好
- 到达日 / 离境日强度
- 其他明确的硬限制 / 软偏好

详细枚举在 Preference Schema / Master Data 冻结前不得由 Codex 自行新增业务规则。

---

## 8. 重置偏好

页面底部提供低视觉优先级的：

`重置偏好`

规则：

1. 不使用危险红色大按钮抢占视觉。
2. 点击后必须二次确认。
3. 明确说明只重置长期偏好，不删除账户、同行人或已保存旅行。
4. 重置后双 Radar、旅行画像和六张摘要卡同步恢复默认状态。

---

## 9. 保存与同步规则

### 9.1 首页画像

Radar 和旅行画像不直接编辑，不存在单独“保存画像”按钮。

它们由底层长期偏好自动计算。

### 9.2 快速设置

中项目快速设置可采用即时保存，并显示轻量反馈：

```text
✓ 已保存
```

### 9.3 详细设置

进入较复杂的详细页面后，可使用：

```text
[恢复默认]      [取消] [保存]
```

避免一次修改多个小项目时频繁提交。

### 9.4 修改后的反馈

用户保存详细偏好后：

```text
底层偏好更新
↓
Radar 重新计算
↓
旅行画像文案更新
↓
摘要卡更新
```

用户必须能直观看到“我的设置真的改变了旅行画像”。

## 10. 长期偏好与本次旅行覆盖

必须冻结以下行为：

```text
个人中心长期偏好：少步行

某次旅行临时设置：这次步行接受度高
```

结果：

- 当前 Trip 使用“步行接受度高”。
- Personal Center 仍保留“少步行”。
- Trip 临时偏好不能静默反写长期偏好。

如未来提供“保存为我的长期偏好”，必须是用户明确触发的独立操作。

## 11. 视觉规范

视觉必须严格延续 WBS 1.21 已确认的 Personal Center 主风格。

### 11.1 页面 Shell

必须复用：

- 左侧固定 Personal Sidebar
- TravelAssist Logo
- 用户头像 / 名称
- 五项一级导航
- 左侧底部鸟居水景插画区域
- 右上通知与头像入口

不得为偏好页面重新设计另一套 Sidebar。

### 11.2 主背景

继续使用：

- 暖米白 / 象牙白
- 非常淡的和纸感
- 极轻樱粉水彩纹理
- 少量青海波 / 金粉细节

禁止：

- 在右侧主背景铺巨大富士山
- 大面积寺庙 / 鸟居背景
- 大段日文 / 中文装饰文字
- 多套日本元素同时抢视觉

### 11.3 图片规则

偏好中心的内容图片必须采用**写实摄影风格**。

适用于：

- 两个 Radar 旁的辅助照片
- 六张偏好摘要卡

例如：

- 移动 → 写实铁路 / 新干线
- 景点与活动 → 写实自然 / 历史场景
- 餐饮 → 写实当地料理
- 住宿 → 写实住宿空间
- 预算 → 写实旅行物件 / 钱包 / 行程资料
- 旅行体验 → 写实摄影 / 当地体验场景

不得把这些旅行内容画成水彩插画。

### 11.4 色调

继续执行个人中心已冻结规则：

- 整体饱和度 / 对比度较高饱和概念稿降低约 10%
- 不得变成灰色后台
- 保留温暖、开心、让人想旅行的氛围
- CTA / 选中态使用珊瑚朱红
- 卡片 Border 使用极淡暖粉褐

## 12. Empty / Partial State

### 12.1 新用户无偏好

Radar 不伪造明确画像。

可以显示柔和默认形状，并提示：

```text
还没有形成完整的旅行画像
设置几项偏好后，TravelAssist 会在这里为您整理旅行风格。
```

并提供：

`开始设置偏好`

### 12.2 部分偏好已设置

允许 Radar 根据已有数据部分生成，但需要避免把缺失数据误解为“不喜欢”。

未设置项应使用“未设置”语义，不直接等同于最低分。

具体默认值与数据行为由 WBS 5.11 / 5.13 冻结。

## 15. 开发实现约束

1. 必须复用 Personal Center Shell，不另建一套账户 / 偏好侧栏。
2. 双 Radar 是长期偏好的可视化，不是独立事实源。
3. 景点偏好 Radar 固定使用：自然 / 历史 / 人文 / 艺术 / 摄影 / 活动体验。
4. 旅行风格 Radar 固定使用：轻松 / 经典 / 计划 / 探索 / 参与 / 深度。
5. 首页不显示百分比评分。
6. 用户修改偏好后，Radar、文字画像和摘要卡必须同步变化。
7. 六个首页详细入口固定为：移动 / 景点与活动 / 餐饮 / 住宿 / 预算 / 旅行体验。
8. 同行人不在 1.25 重复管理，进入 WBS 1.26。
9. 日期 / 行程长度不作为长期偏好卡，留在 Planner。
10. 详细设置继续遵守 A 的“大 → 中 → 小”三级结构。
11. 偏好项目、Master Data、硬 / 软限制不得由 Codex 擅自扩充。
12. 真实旅行内容图片必须使用写实摄影，不使用水彩景物卡片。
13. 视觉必须遵守 WBS 1.21 方案 D 的米白、樱粉、珊瑚朱红与低对比度方向。
14. 本次旅行临时偏好不得自动覆盖个人中心长期偏好。

## 17. 最终冻结结论

WBS 1.25 正式结论：

> **TravelAssist 旅行偏好中心采用“两个六边形偏好画像 + 一句话旅行画像解读 + 六个详细偏好摘要卡”的首页结构。景点偏好画像使用自然、历史、人文、艺术、摄影、活动体验六轴；旅行风格画像使用轻松、经典、计划、探索、参与、深度六轴。详细设置继续复用 A 已确定的大 / 中 / 小三级偏好结构。Personal Center 保存长期默认偏好，Planner 的本次旅行临时设置不会自动反写长期偏好。整体视觉严格延续 WBS 1.21 的 Personal Center 方案 D：暖米白、樱粉与珊瑚朱红，背景做减法，真实旅行内容统一使用写实摄影，并适度降低约 10% 的饱和度和对比度。**

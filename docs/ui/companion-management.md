## 1. 页面定位

同行人管理页用于保存和管理用户长期可复用的同行人资料，使用户在创建新旅行时可以快速选择同行者，而不需要每次重新填写年龄、身份与特殊需求。

核心目标：

1. 快速看懂“我有哪些常用同行人”。
2. 快速看懂同行人的年龄层与旅行相关需求。
3. 支持创建“常用出行组合”，用于 Planner 一键选人。
4. 同行人资料作为长期资料保存；本次旅行可以临时调整，但不会反向覆盖长期资料。
5. 与 Planner / Preference Contract 共用同一套结构化同行人数据，避免形成两套业务规则。
6. 页面保持旅游产品的温暖感，而不是做成通讯录或后台管理页。

## 2. 与其他模块的边界

### 2.1 与 1.25 偏好管理中心

1.25 管理的是“用户长期旅行偏好”。

1.26 管理的是“可复用同行人资料”。

```text
长期旅行偏好
→ 我喜欢怎样旅行

同行人资料
→ 和我一起旅行的人是谁、有哪些旅行相关需求
```

同行人的特殊需求可以影响 Planner，但不直接成为“我的长期偏好”。

### 2.2 与 Planner 的关系

Planner 创建旅行时：

```text
选择同行人
↓
读取同行人资料
↓
组合成本次 Trip Companion Snapshot
↓
影响路线 / 节奏 / 景点 / 餐饮 / 住宿建议
```

例如：

- 儿童 → 儿童友好、休息频率、用餐时间
- 幼儿 → 婴儿车、儿童座椅、少步行等需求
- 长者 → 可按用户明确设置的移动需求参与规划
- 饮食限制 → 餐饮推荐过滤 / 提醒

**重要规则：**

> Planner 只能读取用户明确保存的资料，不根据年龄或身份自动推断医疗、行动能力或其他敏感情况。

# 3. 视觉基准

严格沿用 1.21 已冻结的 Personal Center 视觉语言。

## 3.1 Shell

保持：

- 左侧固定 Personal Center Sidebar
- TravelAssist Logo

- 一级导航：
  - 我的首页
  - 我的旅行

# 5. 顶部摘要区

顶部使用一张横向摘要卡，不做复杂 Dashboard。

建议显示：

```text
同行人总数  4

成人 2
儿童 1
幼儿 1
长者 0

[ + 添加同行人 ]   [ 创建常用组合 ]
```

## 5.1 年龄层统计

推荐统一使用：

- 成人
- 儿童
- 幼儿
- 长者

底层如果 A 的 Contract 仍需要 adultMale / adultFemale / child / infant，可在数据层映射；UI 不必把成人强制拆成男女统计。

原因：

- 对普通用户更自然。
- 避免首页显示过多个人属性。
- 性别可作为同行人资料的可选字段，而不是主要分类。

# 6. 我的同行人

页面核心区域。

## 6.1 人物卡结构

每张卡包含：

```text
┌──────────────────────┐
│   写实头像        ⋯  │
│                      │
│ Haru · 8岁           │
│ 家庭成员 · 儿童       │
│                      │
│ [需儿童座椅]          │
│ [喜欢动物]            │
│ [少步行]              │
└──────────────────────┘
```

建议每张卡只显示 **最多 3 个最重要标签**。

标签过多时：

```text
+3
```

点击进入详情。

## 6.2 本人

用户本人也可以显示在同行人列表，但必须有明确区别：

```text
Yuki
本人
```

本人资料来源：

- Profile 基本信息
- 用户自己的旅行相关特殊需求

本人卡不允许“删除”。

## 6.3 旅行负责人

如未来需要 Trip Owner / 负责人概念，可以在旅行层决定。

**不建议在长期同行人资料中永久标记“旅行负责人”**，因为不同旅行负责人可能不同。

---

# 7. 添加同行人

点击：

```text
+ 添加同行人
```

使用右侧 Drawer 或居中 Dialog。

推荐 Desktop 使用 **右侧 Drawer**，因为用户可以保留同行人列表作为上下文。

## 7.1 基本资料

字段建议：

| 字段 | 必填 | 说明 |
|---|---|---|
| 昵称 / 称呼 | 是 | 卡片主要名称 |
| 关系 | 否 | 家人 / 朋友 / 同事 / 其他 |
| 出生日期 | 否 | 优先于直接保存年龄 |
| 年龄层 | 是 | 成人 / 儿童 / 幼儿 / 长者 |
| 性别 | 否 | 仅用户主动填写 |
| 头像 | 否 | 可上传或使用默认头像 |

### 年龄规则

若填写出生日期：

```text
出生日期
→ 系统根据旅行日期计算当时年龄
```

不要只保存固定“8岁”，否则几年后资料会过期。

卡片 UI 可以显示：

```text
Haru · 8岁
```

但底层优先使用 Date of Birth。

如果用户不愿提供生日：

```text
只选择年龄层
```

也可以正常使用。

# 8. 旅行相关需求

只收集与旅行规划直接相关、且由用户主动填写的信息。

建议采用标签式分组，不做长问卷。

## 8.1 移动与无障碍

候选：

- 少步行
- 减少楼梯
- 需要婴儿车
- 需要儿童座椅
- 需要无障碍路线
- 需要更多休息

用户未设置时，**不得根据年龄自动开启**。

## 8.2 餐饮

候选：

- 不吃某类食物
- 食物过敏
- 素食
- 儿童餐需求
- 其他饮食说明

其中可能涉及健康/过敏信息，应：

- 明确为用户主动填写
- 默认不公开展示完整内容
- 首页人物卡仅显示简化标签，如“饮食限制”
- 具体信息只在详情中查看

## 8.3 活动与体验

可保存：

- 喜欢动物
- 喜欢户外
- 喜欢博物馆
- 喜欢拍照
- 喜欢游乐设施

这类偏好属于“该同行人的个人倾向”，与 1.25 用户本人长期偏好分开保存。

# 9. 编辑同行人

人物卡右上角：

```text
✎ / ⋯
```

建议菜单：

```text
编辑资料
加入常用组合
复制同行人（可选）
删除同行人
```

删除需要二次确认。

```text
删除 Haru？

删除后不会影响已经保存的历史旅行，
但未来旅行将无法再选择该同行人。

[取消] [删除]
```

# 10. 常用出行组合

这是 1.26 的重要功能。

例如：

```text
家庭出游
Yuki + Haru + Sora + ...

双人旅行
Yuki + ...
```

## 10.1 组合卡

显示：

- 组合名称
- 头像叠放
- 人数
- 一句话场景
- `>` 进入编辑

例如：

```text
家庭出游
○ ○ ○ ○

4 位同行人
常用于家庭旅行 / 亲子出游
```

## 10.2 创建组合

点击：

```text
创建常用组合
```

Drawer：

```text
组合名称 *
[ 家庭出游 ]

选择同行人
☑ Yuki
☑ Haru
☑ Sora
☐ ...

[取消] [保存组合]
```

## 10.3 Planner 使用

创建新旅行时，可以：

```text
选择常用组合
→ 家庭出游
→ 自动选中 4 位同行人
```

但进入具体旅行后仍可增删成员。

# 11. 特殊需求摘要

页面下方或右下设置一个摘要区。

目的不是展示隐私细节，而是让用户知道：

> 当前有哪些同行人资料会明显影响 Planner。

例如：

```text
特殊需求摘要

需要婴儿车        1 人
需要儿童座椅      2 人
饮食限制          1 人
少步行            1 人
```

点击某一项，可显示对应人员。

例如：

```text
需要儿童座椅
Haru、Sora
```

## 11.1 隐私规则

禁止首页直接显示：

- 具体病名
- 具体过敏原明细
- 私人健康说明

首页只显示概括性的“旅行需求”标签。

---

# 12. 搜索 / 排序

MVP 同行人数通常不会很多，因此不建议一开始做复杂搜索。

可以保留轻量排序：

```text
按添加时间
按名称
按最近使用
```

当同行人数超过阈值后再考虑搜索框。

---

# 13. Empty State

如果用户没有添加任何同行人：

```text
还没有保存的同行人

添加家人、朋友或常用旅伴，
以后创建旅行时可以一键选择。

[ + 添加同行人 ]
```

右侧可以保留低对比度写实旅行照片或非常淡的樱花视觉，但不堆装饰。

# 14. 保存与反馈

## 14.1 添加 / 编辑

Drawer 内：

```text
[取消] [保存]
```

保存成功：

```text
✓ 同行人资料已保存
```

轻提示即可，不弹大成功页。

## 14.2 未保存离开

```text
您还有尚未保存的修改。

[放弃修改] [继续编辑]
```

# 15. 与长期偏好 / 本次旅行偏好的关系

需要明确三层：

```text
Person Profile
= 同行人长期资料

User Preference
= 用户本人长期旅行偏好

Trip Companion Snapshot
= 本次旅行实际同行人 + 本次临时调整
```

例如：

```text
Haru 长期资料：
需要儿童座椅

某次日本铁路旅行：
这次不租车
```

本次旅行可以不使用儿童座椅条件，但不能反向删除 Haru 的长期资料。

# 18. 必须遵守的交互规则

1. 不根据儿童、长者身份自动添加敏感或健康类需求。
2. 用户明确保存的需求才进入 Planner。
3. 本次旅行的临时同行人调整不覆盖长期资料。
4. 历史旅行保留当时的 Companion Snapshot，不因后来修改同行人资料而改变。
5. 删除同行人不删除历史 Trip 数据。
6. 本人不可删除。
7. 出生日期可选；如果有生日，年龄按旅行日期动态计算。
8. 首页人物卡最多展示 3 个摘要标签。
9. 具体隐私/健康信息不直接暴露在列表页。

# 行程预约状态联动设计

> 状态：v0.1 / 地图、底部行程条、右侧当前方案预约联动冻结  
> 更新日期：2026-09-05  
> 适用：TravelAssist 行程主页面  
> 关联：`docs/ui/trip-planner.md`、`docs/ui/map-pin-booking-integrations.md`

## 1. 核心原则

预约不作为独立于行程之外的一套系统。

住宿、餐厅、景点门票、长途交通等，一旦用户在地图中选择并加入，就成为 **Trip State 中的正式行程节点**。

统一流程：

```text
地图发现 / 推荐
   ↓
点击“加入预约”
   ↓
加入当前方案
   ↓
底部「行程」时间轴立即出现该项目
   ↓
状态 = 待预约
   ↓
用户通过官方 / 第三方渠道完成预约
   ↓
点击“我已完成预约”或由 Provider 自动回写
   ↓
状态 = 已预约
   ↓
底部时间轴、预约·票务 Tab、地图 Pin、右侧当前方案同步更新
```

核心原则：

> 预约是“行程节点的状态”，不是另一份预约清单。

## 2. 地图中的操作

### 2.1 景点

景点详情中：

- `加入行程`
- 如该景点需要票务 / 时段预约，则显示 `加入预约`

点击后：

- 景点成为当前方案正式节点；
- 放入对应日期与推荐时间；
- 底部行程条立即出现；
- 初始预约状态为 `待预约`。

### 2.2 酒店

用户点击推荐住宿区域：

```text
住宿区域
→ 查看推荐酒店
→ 点击具体酒店
→ 加入预约
```

点击 `加入预约` 后：

- 酒店被设为对应日期的住宿节点；
- 底部行程条出现酒店名称；
- 住宿节点显示入住日期 / 晚数；
- 状态显示 `待预约`。

示例：

```text
20:00
京都站 Hotel A
入住 · 连住 3 晚
[待预约]
```

### 2.3 餐厅

用户点击午餐 / 晚餐推荐区域：

```text
餐饮区域
→ 推荐餐厅
→ 选择餐厅
→ 加入预约
```

加入后底部时间轴直接替换原来的泛化节点。

加入前：

```text
12:30 午餐
祇园推荐区域
```

加入后：

```text
12:30 午餐
祇园 Restaurant A
约 1 小时
[待预约]
```

如果餐厅无需预约：

```text
12:30 午餐
祇园 Restaurant A
[无需预约]
```

## 3. 底部「行程」是预约状态的主展示位置

用户不需要切到专门预约页面才能知道是否订好。

所有正式行程节点在底部时间轴直接显示预约状态。

### 3.1 酒店

显示：

- 酒店名称
- 入住时间
- 连住晚数
- 预约状态

例如：

```text
20:00
京都站 Hotel A
入住 · 3晚
待预约
```

完成后：

```text
20:00
京都站 Hotel A
入住 · 3晚
✓ 已预约
```

### 3.2 餐厅

显示：

```text
18:30
Restaurant B
怀石料理 · 约 1.5 小时
待预约
```

完成后：

```text
18:30
Restaurant B
怀石料理 · 约 1.5 小时
✓ 已预约 · 18:30
```

### 3.3 景点

需要门票 / 时段预约时：

```text
10:00
东京晴空塔
停留约 2 小时
待购票
```

完成后：

```text
10:00
东京晴空塔
10:00 入场
✓ 已购票
```

### 3.4 长途交通

例如：

```text
09:10
京都 → 金泽
新干线
待购票
```

完成后：

```text
09:10
京都 → 金泽
指定席
✓ 已购票
```

## 4. 预约状态视觉规则

不通过大量颜色区分，优先使用文字 + 图标。

建议状态：

- `无需预约`
- `待预约`
- `待购票`
- `预约中`
- `已预约`
- `已购票`
- `现场付款`
- `预约失败`
- `已取消`
- `时间变更`

完成状态使用 `✓ 已预约` / `✓ 已购票`，风险状态允许使用强调色，但不要让整个时间轴因预约状态变成高饱和彩色列表。

---

## 5. 底部「预约·票务」Tab 的定位

保留现有 `预约·票务` Tab，但它不再承担“用户第一次看到预约状态”的职责。

它负责 **集中管理和查看细节**。

- **行程 Tab**：回答“当前路线里哪些东西已经订了？”
- **预约·票务 Tab**：回答“所有待预约 / 已预约项目的详细信息是什么？”

预约·票务 Tab 可显示：

- 日期
- 项目
- 状态
- Provider
- 订单号
- 取消期限
- 入场 / 入住 / 用餐时间
- 凭证
- 外部订单入口
- 修改 / 取消入口

因此：

> 行程 Tab = 状态摘要  
> 预约·票务 Tab = 预约管理

## 6. 右侧「当前方案」增加完成预约入口

当前方案卡片增加：

`完成预约`

示例：

```text
方案1 · 当前方案
东京・富士山经典之旅

待预约 4 项
酒店 1
餐厅 1
景点门票 1
交通 1

[完成预约]
```

### 6.1 何时显示

只有当前方案存在以下状态时显示：

- 待预约
- 待购票
- 预约失败
- 需要重新确认

如果没有待处理项目：

```text
✓ 预约已完成
```

不再显示主 CTA。

---

## 7. 点击「完成预约」

不跳离整个行程页面。

建议打开右侧 / 中央预约处理浮层，按行程顺序列出待办：

```text
待完成预约 4 项

D1
□ 成田 → 东京交通

D2
□ 东京晴空塔门票
□ Restaurant B 晚餐

D4–D6
□ 京都站 Hotel A
```

每一项提供：

- 推荐渠道
- 官方渠道
- 合作平台
- 价格 / 取消条件
- `前往预约`

预约完成后允许：

- Provider API 自动同步；
- 或用户点击 `我已完成预约`。

---

## 8. 完成预约后的即时联动

完成任何一项后，不刷新整页。

同步更新：

```text
Trip State
 ├─ 地图 Pin
 ├─ 底部「行程」
 ├─ 底部「预约·票务」
 ├─ 右侧当前方案待预约数量
 └─ AI Context
```

例如：

### 预约前

```text
当前方案
待预约 4 项
[完成预约]
```

酒店完成后：

```text
当前方案
待预约 3 项
[继续完成预约]
```

全部完成：

```text
当前方案
✓ 关键预约已完成
```

## 9. 地图上的 Pin 变化

加入前：

- 推荐 Pin / 推荐区域

加入当前方案后：

- 正式行程 Pin
- 对应日期
- 若需要预约，显示轻量 `待预约` 标识

完成预约后：

- 正式行程 Pin
- 增加小型完成标识
- 不改变路线本身

不要因为“已经预约”给 Pin 换成完全不同颜色，避免地图层级过乱。

---

## 10. 住宿的特殊规则

酒店与普通景点不同。

加入酒店后立即成为：

- 当日终点 / 住宿节点；
- 次日可能的起点；
- 对连续住宿日期生效。

例如：

```text
京都站 Hotel A
D4–D6 · 3晚
```

Trip State 建立一个住宿预约节点，而不是复制成 3 个独立酒店订单。

底部可在每天显示住宿，但订单实体只有一个。

---

## 11. 餐厅的特殊规则

餐厅加入后必须绑定：

- 日期
- 午餐 / 晚餐 / 特别餐
- 建议时间

如果用户预约的实际时间与原计划不同，例如：

```text
计划：18:30
预约成功：19:00
```

系统应：

1. 把餐厅节点更新为 19:00；
2. 检查上一景点与移动时间；
3. 检查后续行程；
4. 如有冲突提示重新排程。

不能只改“预约状态”而不更新实际行程时间。

---

## 12. 景点的特殊规则

景点预约成功后如果得到固定入场时间：

```text
原建议：10:00–12:00
实际票：10:30 入场
```

Trip State 应将该节点升级为：

`fixed_time = true`

并重新计算当天其余时间。

固定预约默认受“重新生成路线”保护，除非用户明确允许更改。

---

## 13. 外部订单与手动确认

如果用户从 TravelAssist 跳到 Booking / Agoda / TableCheck / 官方网站完成预约，返回 TravelAssist 后提供：

`我已完成预约`

MVP 至少支持：

`标记为已预约`

避免因第三方没有订单回传 API 而阻塞整个体验。

后期可支持自动读取、输入订单号、上传或转发确认信息。

---

## 14. 最终用户路径

### 酒店

```text
点住宿区域
→ 看区域解释
→ 选酒店
→ 加入预约
→ 底部行程出现 Hotel A · 待预约
→ 右侧当前方案 +1 待预约
→ 点击完成预约
→ Booking / Agoda / 官网
→ 完成
→ Hotel A · ✓ 已预约
```

### 餐厅

```text
点餐饮区域
→ 看区域解释
→ 选餐厅
→ 加入预约
→ 时间轴原“晚餐区域”变成 Restaurant B · 待预约
→ 完成预约
→ Restaurant B · ✓ 已预约 18:30
```

### 景点

```text
点景点 Pin
→ 加入预约
→ 时间轴出现景点 · 待购票
→ 完成票务
→ 景点 · ✓ 已购票
→ 固定实际入场时间
```

## 15. 当前冻结决策

- [x] 预约属于行程节点状态，不建立与行程分离的第二套清单。
- [x] 地图中点击“加入预约”后，项目立即进入当前方案。
- [x] 项目加入后，底部「行程」时间轴立即显示名称和预约状态。
- [x] 酒店、餐厅、景点门票、长途交通统一适用此规则。
- [x] 底部「行程」负责预约状态摘要。
- [x] 底部「预约·票务」负责集中预约管理和订单详细信息。
- [x] 右侧当前方案增加“完成预约”CTA。
- [x] 当前方案显示待预约项目数量。
- [x] 全部关键预约完成后 CTA 变为“预约已完成”状态。
- [x] 外部 Provider 完成后可自动回写或由用户手动“标记为已预约”。
- [x] 固定景点 / 餐厅实际预约时间必须回写 Trip State 并重新检查路线。
- [x] 已预约固定时间项目默认受到重新生成路线保护。

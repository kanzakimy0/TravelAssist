# 页面设计一览

> 状态：v0.1 / 第一阶段页面框架

## 1. 页面分类

TravelAssist 页面暂分为：

1. 主系统界面
2. 客户 / 用户界面
3. 账号与辅助界面
4. 后续管理界面

第一阶段优先完成用户可见的 Web 核心流程。

## 2. 第一阶段核心页面

| 页面 | 主要目的 | 优先级 | 当前状态 |
|---|---|---:|---|
| 首页 | 进入旅行规划 / 登录 / AI | P0 | 核心方向已定 |
| 初始需求流程 | 获取目的地、日期、同行人与必要偏好 | P0 | 流程待细化 |
| 行程主页面 | 地图、时间轴、推荐方案、设置、AI | P0 | 核心布局已定 |
| 登录 / 注册 | 账号识别 | P0/P1 | 待设计 |
| 我的旅行 | 查看已保存行程 | P1 | 待设计 |
| 行程详情 / 分享 | 查看已保存方案 | P1 | 待设计 |
| 用户偏好 | 管理长期偏好 | P1 | 待设计 |

## 3. 首页

详见 `home-page.md`。

主要元素：

- 让我们开始吧
- 登录
- AI 浮动入口
- 极简沉浸式背景

## 4. 初始需求流程

目标是让用户尽快进入生成阶段。

优先获取：

- 去哪里
- 日期 / 天数
- 同行人
- 必要硬限制

其余偏好可以：

- 从 AI 自然语言中提取
- 使用快速设置
- 进入主页面后继续调整

不应在首次进入时展示完整高级偏好表单。

## 5. 行程主页面

详见 `trip-planner.md`。

核心区：

```text
地图
├─ 多日路线
├─ 景点
├─ 交通
├─ 推荐住宿区域
└─ 推荐餐饮区域

浮动设置
├─ 关键条件摘要
├─ 中项目快速设置
└─ 小项目详细设置

推荐方案
├─ 推荐 1：详细摘要
├─ 推荐 2：精简
└─ 推荐 3：精简

底部时间轴
└─ 景点 / 活动 / 交通 / 餐饮 / 住宿

AI
└─ 自然语言修改与解释
```

## 6. 我的旅行

第一阶段最低需求：

- 已保存旅行列表
- 日期
- 目的地
- 行程状态
- 打开 / 继续编辑

后续可增加：

- 复制旅行
- 分享
- 归档
- 旅行结束后的回顾

## 7. 用户偏好

需要与“本次旅行偏好”区分。

长期偏好未来可用于新旅行的默认值，但是否自动继承尚未冻结。

## 8. 管理界面

后台管理不是当前首要设计重点。

后续可能包括：

- 内容数据管理
- 景点 / 标签 Master Data
- 推荐规则配置
- AI 成本 / 调用监控
- 用户问题与反馈

具体范围待技术和运营需求明确后再设计。

## 9. 页面导航原则

- 旅行规划核心操作尽量停留在主页面完成。
- 不因为一个小设置频繁跳转新页面。
- 地图、时间轴、设置、AI 共享同一 Trip State。
- 手机 App 阶段可重排布局，但不重写业务含义。

## 10. 未确定事项

- 登录 / 注册具体页面流程。
- 我的旅行的信息密度与卡片样式。
- 分享是否需要独立公开页面。
- 首次需求收集采用独立页面、全屏对话还是首页内渐进展开。
- 后台管理系统第一阶段是否开发。

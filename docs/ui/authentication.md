> 文档版本：v1.0

> Owner：B / Personal Center  
> 状态：**设计已冻结；实现阶段由 5.3 / 8.3 承接**

---

## 1. 设计目标

认证流程必须满足两个目标：

1. 尽量降低用户进入旅行规划的门槛。
2. 保持 TravelAssist 已冻结的“温暖、轻日式、旅行感”视觉，而不是做成普通 SaaS 登录页。

认证页面不使用 Personal Center Sidebar，而使用独立 `Auth Shell`。

```text
Auth Shell
├── 左侧旅行视觉区
└── 右侧认证卡
    ├── 登录
    ├── 注册
    ├── 找回密码
    └── 重设密码
```

## 3. 视觉基准

延续 Personal Center 方案 D，但认证页进一步减法。

### 背景

- 暖米白 / 象牙白
- 极淡和纸质感
- 少量樱粉水彩云雾 / 花瓣
- 轻量青海波纹理
- 不加入大面积富士山、鸟居、寺庙或装饰文字

### 左侧旅行视觉

使用**写实摄影**：

- 京都古街 / 町屋 / 樱花 / 寺塔可作为目的地画面
- 自然光
- 真实摄影质感
- 饱和度与对比度相较高饱和概念图降低约 10%
- 不做水彩照片，不做卡通或 HDR 过强效果

### Auth Card

- 暖米白半透明 / 轻奶白
- 轻暖粉 Border
- 圆角大卡
- 柔和阴影
- 表单输入框保持现代、清晰
- 朱红 / 珊瑚红只承担主 CTA、当前选中状态和关键链接

## 4. 登录页总结构

登录页顶部只保留一层主切换：

```text
[ 手机登录 ]   [ 邮箱登录 ]
```

**不出现第二层“密码登录 / 验证码登录”Tab。**

规则：

- 手机登录：只允许验证码登录
- 邮箱登录：默认密码登录，可在表单内切换到验证码登录

# 5. 手机登录

## 5.1 固定为验证码登录

手机登录没有密码模式。

页面结构：

```text
欢迎回来
登录后继续你的旅程规划

[ 手机登录 ]   邮箱登录

手机号
[ 国家/地区码 ] [ 请输入手机号 ]

验证码
[ 请输入验证码 ] [ 获取验证码 ]

☑ 继续即表示你同意《服务条款》和《隐私政策》
  未注册手机号验证成功后将自动创建 TravelAssist 账户

[ 登录 / 继续 ]

──────── 或 ────────
[ 使用 Google 登录 ]
[ 使用 Apple 登录 ]

还没有账户？ 创建账户
```

## 5.2 手机自动注册规则

```text
手机号 + OTP 验证成功
        ↓
查询手机号是否已有账户
        ↓
已有账户 → 登录
未注册   → 自动创建最小账户 → 登录
```

自动注册只建立必要账号信息，不要求立刻填写 Profile、偏好、同行人等资料。

必须在验证码区域明确提示：

> 未注册手机号验证成功后将自动创建 TravelAssist 账户。

自动注册成功后允许轻提示：

> 已为你创建 TravelAssist 账户。

不得把用户强制导向完整 Profile 填写流程。

# 6. 邮箱登录

## 6.1 默认状态：密码登录

选择 `邮箱登录` 后，不再显示额外模式 Tab。

默认表单：

```text
欢迎回来
登录后继续你的旅程规划

手机登录   [ 邮箱登录 ]

邮箱地址
[ 请输入邮箱地址 ]

密码
[ 请输入密码 ]

                    使用验证码登录   |   忘记密码？

[ 登录 ]
```

### 关键规则

- `使用验证码登录` 和 `忘记密码？` 必须放在**密码输入框外部**。
- 不放进输入框内部。
- 点击 `使用验证码登录` 后，不跳新页面，直接在当前 Auth Card 内切换表单状态。

---

## 6.2 邮箱验证码登录状态

点击 `使用验证码登录` 后：

```text
邮箱地址
[ 请输入邮箱地址 ]

验证码
[ 请输入验证码              | 重新发送 ]

                         使用密码登录

[ 登录 ]
```

交互规则：

1. 原 `密码` 输入框原位切换为 `验证码` 输入框。
2. 验证码输入框右侧提供 `重新发送`。
3. `忘记密码？` 不再显示。
4. 原 `使用验证码登录` 入口变为 `使用密码登录`。
5. 点击 `使用密码登录` 后恢复密码输入框与：
   - `使用验证码登录`
   - `忘记密码？`

邮箱密码 / 邮箱验证码两种状态应该在同一 Auth Card 中轻量切换，不产生整页跳转。

---

## 6.3 邮箱验证码不自动注册

```text
邮箱 OTP 验证成功
      ↓
查询邮箱
      ↓
已注册 → 登录
未注册 → 不创建账户
```

未注册邮箱验证成功后显示：

```text
此邮箱尚未绑定 TravelAssist 账户

[ 创建账户 ]
[ 使用其他邮箱 ]
```

点击 `创建账户`：

- 进入注册页
- 自动预填已经验证的邮箱
- 不要求再次输入该邮箱

**邮箱验证码登录绝不能像手机验证码一样自动注册。**

# 7. 邮箱密码登录

基础字段：

- 邮箱地址
- 密码
- 显示 / 隐藏密码

辅助操作：

- 使用验证码登录
- 忘记密码？

错误场景：

- 邮箱格式错误
- 邮箱未注册
- 密码错误
- 账号受限 / 登录失败

错误文案应在输入框附近清晰显示，不使用 Toast 作为唯一错误反馈。

# 8. 注册页

注册入口从：

- 登录页底部 `创建账户`
- 未注册邮箱 OTP 登录后的 `创建账户`

进入。

第一阶段注册只收最少信息：

```text
创建账户
开启你的下一段旅行规划

邮箱地址
[ Email ]

密码
[ Password ]

确认密码
[ Confirm Password ]

☑ 我已阅读并同意《服务条款》和《隐私政策》

[ 创建账户 ]

──────── 或 ────────
[ 使用 Google 注册 ]
[ 使用 Apple 注册 ]

已有账户？ 登录
```

注册时**不要求**：

- 姓名
- 性别
- 年龄
- 住址
- 旅行偏好
- 同行人
- 预算
- 兴趣

这些内容在后续 Personal Center 中渐进完善。

---

## 8.1 注册成功

成功状态：

```text
账户创建成功 ✓

开始你的第一次旅行

[ 开始规划 ]

稍后完善个人资料
```

不得要求用户先完善 Profile 才能进入旅行规划。

# 9. 找回密码

仅针对邮箱密码体系。

从邮箱密码登录状态点击 `忘记密码？` 进入。

```text
找回密码

输入注册邮箱，我们会发送重设密码链接。

邮箱地址
[ Email ]

[ 发送重设链接 ]

← 返回登录
```

发送成功：

```text
邮件已发送 ✓

我们已向 yu***@example.com
发送密码重设邮件。

[ 重新发送 ]

← 返回登录
```

---

# 10. 重设密码

通过邮件中的有效重设链接进入：

```text
设置新密码

新密码
[ New Password ]

确认新密码
[ Confirm Password ]

[ 更新密码 ]
```

成功后：

```text
密码已更新 ✓

[ 返回登录 ]
```

# 11. Google / Apple 入口

登录页和注册页保留：

- Google
- Apple

作为第三方认证入口槽位。

具体 OAuth Provider、首次登录是否自动建号、账户关联规则由认证技术实现阶段进一步冻结；本 UI 设计不将具体后端方案写死。

任何第三方登录产生的账户绑定 / 合并不得静默覆盖用户已有账号。

---

# 12. 登录后的返回规则

登录成功后不能统一强制进入个人中心，应恢复用户原本上下文。

```text
首页点击登录
→ 登录成功
→ 返回首页 / 原页面

Planner 保存时要求登录
→ 登录成功
→ 返回当前 Planner
→ 继续保存动作

直接访问个人中心
→ 登录成功
→ Personal Center Home
```

认证流程需要支持 `returnTo / redirect intent` 概念。

---

# 13. OTP 行为规范

手机 OTP 与邮箱 OTP 共用基础状态：

```text
Idle
Sending
Sent
Countdown
CanResend
Verifying
Success
Error
Expired
```

### 重新发送

- 验证码发送成功后进入倒计时
- 倒计时结束前不可重复发送
- 倒计时结束后显示 / 启用 `重新发送`
- 邮箱验证码模式中 `重新发送` 位于验证码输入框右侧
- 手机验证码模式可使用 `获取验证码 / 重新发送` 同一按钮位置

具体验证码有效期、倒计时秒数、频率限制由认证技术实现阶段冻结，不在 UI 设计中写死。

---

# 14. 输入框与状态

所有输入框至少覆盖：

```text
Default
Focus
Filled
Error
Disabled
Success（必要时）
```

输入框建议高度约 48–52px 视觉规格。

错误状态不能只靠颜色表达，应提供文字说明。

密码框支持显示 / 隐藏密码。

---

# 15. 密码规则

注册 / 重设密码时提供简洁的实时规则反馈。

例如：

```text
✓ 至少 8 个字符
✓ 包含字母
○ 包含数字
```

不要制作复杂评分器或大量密码说明。

实际密码策略由 Authentication 核心实现阶段最终确定。

---

# 16. 账户唯一性与绑定原则

第一阶段设计约束：

- 同一个手机号只允许绑定一个账户
- 同一个邮箱只允许绑定一个账户
- 手机自动注册账户后，未来可以在 Personal Center 中绑定邮箱 / 设置密码
- 不允许因为邮箱重复而静默自动合并两个账户
- 账户合并 / 绑定必须经过明确身份验证

# 17. 核心状态机

## 17.1 手机登录

```text
Phone Login
→ 输入手机号
→ 获取 OTP
→ 输入 OTP
→ 验证成功
   ├─ Existing User → Login
   └─ New Phone → Auto Sign-up → Login
```

## 17.2 邮箱密码登录

```text
Email Login
→ Password Mode
→ Email + Password
→ Login
```

## 17.3 邮箱验证码登录

```text
Email Login / Password Mode
→ 使用验证码登录
→ Password Field 变为 OTP Field
→ 获取 / 输入 OTP
→ 验证成功
   ├─ Existing User → Login
   └─ Unregistered Email → Show Create Account CTA
```

## 17.4 邮箱模式切换

```text
Password Mode
├─ 使用验证码登录 → OTP Mode
└─ 忘记密码 → Forgot Password

OTP Mode
└─ 使用密码登录 → Password Mode
```

# 21. Codex / 开发实现约束

1. 登录页第一层只有 `手机登录 / 邮箱登录`。
2. 手机登录固定为验证码，不提供手机密码登录。
3. 未注册手机号 OTP 验证成功后自动注册并登录。
4. 手机自动注册前必须可见服务条款 / 隐私政策说明。
5. 邮箱登录默认显示 Email + Password。
6. 邮箱密码输入框外显示 `使用验证码登录 | 忘记密码？`。
7. 点击 `使用验证码登录` 后原密码输入框原位变成验证码输入框。
8. 邮箱验证码输入框右侧提供 `重新发送`。
9. 邮箱 OTP 状态下原入口切换成 `使用密码登录`，不显示 `忘记密码？`。
10. 邮箱 OTP 验证成功但邮箱未注册时，不得自动创建账户。
11. 注册页只收最小必要信息，不强制填写 Profile / Preferences。
12. 登录成功必须支持恢复原页面上下文。
13. 左侧旅行视觉使用写实照片，整体视觉延续个人中心方案 D 并降低约 10% 饱和度 / 对比度。
14. 不把认证页做成传统后台 / SaaS 登录模板。

# 23. 最终冻结结论

> **TravelAssist 认证页采用独立 Auth Shell：Desktop 以左侧写实旅行摄影 + 右侧暖米白认证卡构成。登录仅提供“手机登录 / 邮箱登录”一级切换。手机固定为验证码登录，未注册手机号验证成功后自动创建账户；邮箱默认密码登录，可通过密码框外的“使用验证码登录”在同一表单中切换 OTP 模式，OTP 模式提供重新发送与“使用密码登录”，且未注册邮箱绝不自动注册。注册、找回密码、重设密码均沿用同一 Auth Shell，并保持低摩擦、低信息密度与轻日式旅行感。**

# 1. 设计目标

1.28 负责用户账户中真正涉及安全、授权和数据生命周期的页面，不重新承担 1.24 的个人资料编辑。

核心目标：

1. 让用户清楚知道自己可以通过哪些方式登录。
2. 安全修改邮箱、手机号、密码和第三方登录方式。
3. 管理当前登录设备 / Session。
4. 在高风险操作前要求重新验证身份。
5. 提供个人数据导出。
6. 提供清楚、不可误解的账户删除流程。
7. 将最新“预订与账户同步”能力纳入账户体系，但不把 Booking / Agoda 等做成一级导航。
8. 明确：**删除 TravelAssist 账户不会自动取消 Booking.com、Agoda、Klook 等外部订单。**

# 8. 密码

由于 1.23 支持“手机号验证码自动注册”，部分用户可能没有密码。

因此 UI 必须支持两个状态。

## 已设置

```text
密码
已设置

[修改密码]
```

## 未设置

```text
密码
尚未设置

设置密码后，也可以使用邮箱 + 密码登录。

[设置密码]
```

密码修改需要：

- 当前密码，或
- 最近完成过一次强身份验证。

“忘记当前密码”继续进入 1.23 已冻结的邮箱重置流程。

# 9. 第三方登录方式

预留：

```text
Google
已连接
[管理]

Apple
未连接
[连接]
```

规则：

1. 连接第三方登录需要重新确认当前账户。
2. 断开登录方式前检查是否仍存在其他可用登录方式。
3. **不得允许用户断开最后一种可用登录方式。**
4. 不自动合并疑似重复账户。
5. Google / Apple 的具体 OAuth 注册政策继续服从 1.23 后续认证实现。

# 10. 高风险操作重新验证

以下操作必须触发 Re-authentication：

- 修改邮箱
- 修改手机号
- 修改 / 设置密码
- 断开关键登录方式
- 退出全部设备
- 导出个人数据
- 删除账户
- 连接或断开敏感外部同步账户

验证方式根据用户已有 Login Method 动态选择：

```text
手机验证码
邮箱验证码
当前密码
第三方重新授权
```

不要强迫手机号登录用户去输入不存在的密码。

# 17. 删除账户——原则

这是 1.28 最重要的危险流程。

必须明确区分：

```text
删除 TravelAssist 账户
≠
取消 Booking / Agoda / Klook / 航空公司等 Partner 订单
```

Partner 仍是外部订单的 Source of Truth。

---

# 18. 删除账户 Step 1：影响说明

点击 `删除账户` 后进入专用 Dialog / Page，不直接删除。

```text
删除您的 TravelAssist 账户？

将删除或进入删除流程的数据包括：
• 个人资料
• 长期旅行偏好
• 同行人资料
• TravelAssist 中保存的旅行与收藏
• TravelAssist 保存的外部订单映射与同步记录
• 账户连接与授权

不会自动取消：
• Booking.com 酒店
• Agoda 酒店
• Klook / Viator / GetYourGuide 门票
• 餐厅预约
• 航班 / 铁路 / 租车等外部订单
```

# 23. 删除账户后的状态

删除请求成功：

```text
您的账户删除请求已提交
```

随后：

- 当前 Session 退出。
- 第三方授权 Token 进入撤销流程。
- 不再自动同步 Booking / 邮件等外部数据。
- 外部 Partner 订单保持原状态。

**具体立即删除 / 宽限期 / 法定保留时间不在 1.28 UI 设计中硬编码。**
正式实现时必须根据最终隐私政策显示真实期限。

# 27. 连接 Booking / Provider 的安全规则

1. TravelAssist 不要求用户输入或保存 Provider 密码。
2. 使用 OAuth / Partner 授权能力时，清楚显示授权范围。
3. 断开连接只停止未来同步。
4. **断开连接不会取消 Partner 订单。**
5. 已经写入 Trip 的 Reservation Record 是否保留，由用户单独管理；默认保留历史记录。
6. 如果 Provider 授权到期，已有 Trip 不应突然删除。

# 34. 最终冻结项

- 账户子页面仍运行在 1.21 Personal Center Shell。
- 1.24 Account Overview 增加“预订与账户同步”第三入口。
- Login Method 支持邮箱 / 手机 / 密码 / Google / Apple 状态。
- 手机验证码注册用户允许“没有密码”。
- 不允许移除最后一种登录方式。
- 高风险操作要求 Re-auth。
- 提供登录设备 / Session 管理。
- 提供最近安全活动。
- 提供完整账户数据导出。
- 删除账户前检查未来旅行与外部订单。
- 删除 TravelAssist 账户绝不等于取消外部订单。
- 删除前提供数据导出建议。
- 删除最终确认使用专用 Danger Red。
- “预订与账户同步”使用已冻结的连接状态。
- 断开 Provider 只停止同步，不取消订单。
- Provider 密码不由 TravelAssist 保存。
- 手动导入保持免费可用。

- 会员订阅取消与账户删除的账单规则。

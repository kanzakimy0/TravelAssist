# 首页设计

> 状态：v0.2 / 核心入口与视觉方向已确定，具体视觉 Token / 动画技术待冻结

## 1. 页面目标

首页不是传统营销落地页，而是尽快把用户带入旅行规划。

核心原则：

- 极简
- 圆润
- 沉浸式
- 少宣传语
- 明确主入口
- AI 随时可用

## 2. 核心元素

### 主入口

- `让我们开始吧`
- 优先级最高
- 点击后进入旅行需求收集 / AI 规划流程

### 登录

- 作为次级入口
- 不抢占主视觉

### AI 按钮

- 固定于右下角
- 点击后展开对话
- 用户可以不经过传统表单直接描述旅行需求

### 顶部导航

- 顶部选单栏尽量小
- 避免传统网站大面积导航占用
- 第一阶段只保留真正必要的入口

## 3. 视觉方向

### 已确认

- 极简留白
- 圆角 UI
- 轻量日本元素
- **动态旅行画面 / 动画背景作为首页视觉方向**
- 可参考 Komoot 的沉浸式视觉和地图产品感，但不直接复制
- UI 控件应像浮在背景 / 地图上的卡片，而不是传统网页模块堆叠
- 不采用绿色作为主要视觉方案

### 动态背景说明

“动态背景”本身已确认，但具体实现技术尚未决定。可在技术验证阶段比较：

- 视频
- Lottie
- WebGL
- 轻量 CSS / Canvas 动画

第一版工程可以先使用静态 / 轻量占位层，但组件结构必须允许后续替换为动态背景，不能把静态图片写死为最终方案。

### 色彩待确认

- 最终主色
- 辅助色
- 背景明暗方案
- 动态背景的色彩统一策略

## 4. 交互流程

```text
首页
├─ 让我们开始吧
│   └─ 进入旅行需求流程
├─ 登录
│   └─ 账号流程
└─ AI
    └─ 展开对话 → 直接开始规划
```

## 5. AI 展开状态

AI 面板应保持轻量：

- 不把整个页面切换成传统聊天页面
- 以浮层 / 镶嵌卡片方式出现
- 能继续看到首页背景上下文
- 后续进入行程主页面后，AI 入口仍然存在

## 6. 响应式考虑

桌面端：

- 允许大面积动态视觉背景
- 主入口保持明确
- 顶部导航保持紧凑

移动端：

- 背景视觉不能挤压主要操作
- AI 浮层应适配单手操作
- 登录与主入口应保持清晰层级
- 需要考虑 `prefers-reduced-motion` 和低性能设备的背景降级

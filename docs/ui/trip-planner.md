# 行程主页面详细设计

> 状态：v0.2 / 当前页面布局与核心交互已冻结  
> 更新日期：2026-09-05  
> 适用：TravelAssist Web 桌面端行程主页面

## 1. 页面定位

行程主页面是 TravelAssist 的核心旅行工作区。

页面职责按三个区域严格区分：

- **地图 = 空间**：地点、路线、区域关系、交通段、地图图层。
- **右侧栏 = 整趟旅行的决策与方案**：同行人、日期、偏好、高级设置、路线重算、方案切换。
- **底部栏 = 当天执行**：行程、移动、预约票务、天气备选、住宿餐饮与详细信息。

设计原则：

1. 地图始终是页面视觉主体。
2. 右侧栏宽度约为页面 **1/4**，不能产生接近 1/3 的视觉重量。
3. 底部信息条高度约为页面 **1/4**。
4. 右侧栏延伸到底部；底部信息条只覆盖地图区域，不进入右侧栏。
5. 页面缩小到指定响应式阈值后：
   - 右侧栏折叠成单一入口按钮；
   - 底部信息条折叠成单一入口按钮。
6. 响应式具体像素断点由实现阶段依据实际内容密度确定；**折叠行为本身已冻结**。

## 2. 整体布局

宽屏桌面端以 16:9 为主要设计基准。

```text
┌──────────────────────────────────────────────────────────────┐
│ 顶部导航                                                     │
├──────────────────────────────────────────────┬───────────────┤
│                                              │               │
│                 地图主区域                   │   右侧栏      │
│                ≈ 页面 3/4                    │  ≈ 页面 1/4   │
│                                              │               │
│ 左侧可隐藏图层栏        日程范围选择器         │ 上半：设置     │
│                                              │               │
│ 路线 / 地点 / 交通 / 区域                    ├───────────────┤
│                                              │ 下半：方案     │
│                                              │               │
├──────────────────────────────────────────────┤               │
│              底部信息条 ≈ 页面高 1/4          │               │
│ 行程｜移动｜预约票务｜天气备选｜住宿餐饮｜详细 │               │
└──────────────────────────────────────────────┴───────────────┘
```

### 2.1 视觉比例

- 地图 + 底部栏所在左侧工作区：约 **75% 页面宽度**。
- 右侧栏：约 **25% 页面宽度**。
- 右侧栏内部：
  - 上半设置区：约 50%；
  - 下半方案区：约 50%；
  - 两部分必须**紧贴、连续、属于同一个右侧容器**，不要做成上下相距很远的独立卡片。
- 底部栏：约 **25% 页面高度**，覆盖左侧地图工作区。

## 3. 视觉风格

整体色调以当前账户页面设计为准。

### 3.1 色彩

- 主背景：暖白、象牙白、低饱和米色。
- 辅助装饰：非常淡的樱花粉 / 暖粉。
- 正文：深蓝灰 / 深墨色。
- 边框：低对比暖灰粉。
- 强调按钮：克制的珊瑚粉 / 暖红。
- **除行程路线外，不使用大量高饱和颜色。**
- 地图 Pin、功能图标、状态标签均应减少无必要的多色混用。

### 3.2 卡片

- 大圆角。
- 轻阴影。
- 轻微半透明 / 镶嵌在地图上的感觉。
- 不使用强烈玻璃拟态。
- 卡片之间间距紧凑但不拥挤。

### 3.3 地图路线

路线是页面中允许保留较明显色彩对比的主要元素。

- 当前查看路线可使用明确主色。
- 多日路线需要区分时，颜色数量应克制。
- 不依赖颜色作为唯一识别方式，同时使用 Day / 日期 / 节点标签。

---

## 4. 地图主区域

地图负责空间关系，不负责重复展示旅行摘要。

### 4.1 左上角

**不显示行程概览卡。**

删除：

- 行程名称大卡片
- 日期摘要
- 天气摘要
- 同行人摘要
- 目的地封面

这些信息已在右侧栏与底部栏中存在，不得重复占用地图面积。

### 4.2 地图内容

地图可展示：

- 当前方案路线
- 每日路线
- 景点 Pin
- 住宿
- 餐饮区域
- 交通节点
- 已预约活动
- 推荐区域
- 当前定位
- 路线段交通方式与时间

景点选中后可显示小型地点卡，但不得恢复成左上角大型行程概览。

---

## 5. 左侧地图图层栏

地图左侧保留快速图层 / 分类工具栏。

建议项目：

- 图层
- 景点
- 交通
- 酒店 / 住宿
- 餐饮
- 已订 / 已预约活动
- 更多
- 当前定位（如需要）

### 5.1 收起与展开

左侧栏必须支持手动隐藏：

- 展开：显示图标 + 文字。
- 收起：只保留一个小型展开按钮。
- 收起后地图获得完整空间。
- 再次点击恢复。

该栏属于地图工具，不属于行程设置。

---

## 6. 地图日程范围选择器

在**地图最右侧、右侧栏左边**设置一个紧凑的日程范围选择器。

基础模式：

- `1日`
- `3日`
- `全日`

### 6.1 选择 1 日

点击 `1日` 后，原 `1日` 按钮变成当天选择下拉菜单。

示例：

```text
第1天 ▼
3日
全日
```

下拉内容：

- 第1天
- 第2天
- 第3天
- ...
- 第N天

用户选择某一天后：

- 地图仅突出该天路线；
- 底部行程内容同步到该天；
- 地图自动调整合适视野。

### 6.2 选择 3 日

点击 `3日` 后，原 `3日` 控件变成：

```text
从第1天开始的3天 ▼
```

或等价紧凑文案：

```text
Day 1–3 ▼
```

下拉内容根据行程总天数动态生成：

- 从第1天开始的3天
- 从第2天开始的3天
- 从第3天开始的3天
- ...

不足 3 天的尾段不生成无效组合。

用户切换后：

- 地图同时显示连续 3 天路线；
- 自动调整地图视野覆盖这 3 天；
- 底部栏同步对应 3 天的时间范围。

### 6.3 选择全日

点击 `全日`：

- 显示完整旅行路线；
- 自动适配整趟行程地图边界；
- 不显示起始日下拉菜单。

---

## 7. 右侧栏

右侧栏固定为页面约 **1/4 宽度**，并延伸到页面底部。

不再设置顶部：

- `详细设置`
- `行程方案`

两种页签。

用户直接看到设置与方案。

### 7.1 右侧栏整体结构

```text
┌──────────────────────┐
│ 同行人      旅行日期  │
│                      │
│ 景点   餐饮   住宿    │
│                      │
│ 更多行程设置  重新生成路线 │
│                      │
│    上半设置区 50%     │
├──────────────────────┤
│ 推荐方案              │
│ 方案1  [当前方案]      │
│ 方案2                 │
│ 方案3                 │
│                      │
│    下半方案区 50%     │
└──────────────────────┘
```

上下部分紧贴，视觉上是一个连续整体。

## 8. 右侧栏上半部分：旅行设置

### 8.1 第一排：同行人与旅行日期

两个并排选项卡：

#### 同行人
摘要示例：

- 2位成人
- 2成人 · 1儿童
- 家庭

#### 旅行日期
摘要示例：

- 4月10日–4月12日
- 3天2晚

---

### 8.2 第二排：三类核心偏好

三个并排选项卡：

#### 景点偏好
摘要：

- 自然风光
- 经典地标
- 摄影

#### 餐饮偏好
摘要：

- 当地美食
- 日料
- 咖啡 / 甜品

#### 住宿偏好
摘要：

- 舒适型
- 靠近车站
- 温泉酒店

详细内容点击卡片后再编辑，不在默认状态全部铺开。

## 9. 更多行程设置

### 9.1 默认状态

`更多行程设置` 默认**不展开**。

与 `重新生成路线` 放在同一行。

布局原则：

- 两个按钮同一高度、同一视觉等级；
- `更多行程设置` 可略宽，以保证文字与图标舒展；
- `重新生成路线` 位于右侧，必须始终存在；
- 两者整体保持接近 1:1，不可让其中一个按钮明显过小。

### 9.2 点击行为

点击 `更多行程设置` 后：

- 在按钮原位置附近弹出 Popover / 浮动菜单；
- 浮层覆盖在当前页面之上；
- **不得撑开右侧栏；**
- **不得推动推荐方案向下移动；**
- **不得改变地图、底部栏或整个页面布局。**

再次点击、点击关闭按钮或点击浮层外部即可关闭。

### 9.3 浮层内容

包含：

- 预算
- 旅行节奏
- 移动偏好
- 时间偏好
- 拥挤与排队
- 摄影与观景
- 已预约活动
- 特殊需求
- 行李设置
- 天气策略
- 方案约束
- 更多筛选

其中浮层顶部优先并排：

#### 预算
- 主值：中等预算
- 小字：¥15,000–25,000 / 人 / 天

#### 旅行节奏
- 主值：偏轻松
- 小字：每天 2–4 个主要地点

## 10. 重新生成路线

`重新生成路线` 位于 `更多行程设置` 右侧。

点击逻辑：

1. 读取当前同行人、日期、三类偏好以及高级设置。
2. 保留明确锁定的预约 / 必去点 / 不可修改条件。
3. 重新计算路线与每天节奏。
4. 生成新的推荐方案或更新当前方案。
5. 同步更新地图、底部栏与右侧方案区。
6. 应向用户展示变化摘要，避免“无说明直接替换”。

---

## 11. 右侧栏下半部分：推荐方案

下半部分与上半部分约 **1:1 面积**。

方案区不再使用大卡 + 两个方卡组合。

固定采用 **3 个横向方案条**，上下排列：

```text
方案1  东京·富士山经典之旅       >
方案2  深度体验之旅              >
方案3  轻松休闲之旅              >
```

### 11.1 当前方案

当前选中方案必须有：

- 完整外框；
- 低饱和强调边框；
- `当前方案` 或 `已选中` 小字标签；
- 方案名称；
- 关键差异标签；
- 必要的简短指标。

当前方案不得只依靠背景颜色区分。

### 11.2 其他方案

方案 2、方案 3 使用同尺寸横条：

- 缩略图
- 方案编号
- 方案名称
- 一句核心差异 / 若干紧凑标签
- 进入 / 切换箭头

点击后：

- 该方案成为当前方案；
- 外框和 `当前方案` 标签同步切换；
- 地图和底部栏同时更新。

---

## 12. 底部信息条

底部信息条覆盖地图区域，默认高度约 **页面高度的 1/4**。

它不是“简单景点列表”，而是**当天执行控制台**。

### 12.1 六个一级选项卡

从左到右：

1. **行程**
2. **移动**
3. **预约·票务**
4. **天气·备选**
5. **住宿·餐饮**
6. **详细**

`行程` 为默认打开项。

---

## 13. 底部：行程

负责回答：

> 今天几点做什么？

显示：

- 时间
- 景点 / 活动
- 停留时间
- 午餐
- 晚餐
- 入住
- 下一段交通
- 固定时间状态

示例：

```text
08:30 抵达
10:00 浅草寺
12:30 午餐
14:00 东京晴空塔
17:00 银座
20:00 入住酒店
```

地图与时间轴双向联动：

- 点击时间轴节点 → 地图定位。
- 点击地图地点 → 底部节点高亮。
- 调整行程后 → 重新计算受影响路线与时间。

---

## 14. 底部：移动

负责回答：

> 下一站怎么去？

显示：

- 驾车
- 火车 / 电车
- 公交
- 步行
- 渡轮
- 停车
- 酒店接驳
- 预计耗时
- 距离
- 换乘
- 必要的道路 / 山路 / 通票信息

时间轴只展示简要移动结果；详细移动过程进入此页签。

---

## 15. 底部：预约·票务

负责：

- 固定时段景点
- 导览预约
- 门票
- 餐厅预约
- 城市卡 / 通票
- 演出
- 酒店固定入住条件
- 已购 / 待购
- 报到提前量
- 取消截止时间

关键预约必须在当天时间轴中同步标记。

---

## 16. 底部：天气·备选

负责：

- 当天天气
- 天气风险
- 日出 / 日落
- 山区能见度
- 强风 / 降雪 / 高温等
- 雨天路线
- 室内备选
- 天气变化后的路线替代方案

支持一键将当前天气备选路线应用到当天行程。

---

## 17. 底部：住宿·餐饮

### 住宿

显示：

- 今晚酒店 / 推荐住宿区域
- 入住时间
- 停车
- 联系方式
- 订单入口
- 明早退房
- 下一目的地

### 餐饮

显示：

- 午餐安排
- 晚餐安排
- 推荐区域
- 是否预约
- 价格层级
- 与当前路线的关系

---

## 18. 底部：详细

`详细` 用于承载不适合挤在前五个执行页签里的当日深层信息。

可包括：

- 当天完整说明
- 地址 / 营业时间
- 联系方式
- 重要备注
- 费用明细
- 订单 / 文件入口
- 特殊注意事项
- AI 对当天安排的解释
- 不影响主要时间轴但需要查看的信息

设计目标：

> 前五个 Tab 用于快速执行，`详细` 用于需要时深入查看。

---

## 19. 底部栏响应式折叠

当页面宽度或可用地图高度低于指定阈值：

- 底部栏整体折叠成一个小型按钮；
- 地图释放垂直空间；
- 点击按钮以浮层 / 抽屉方式重新展开底部内容；
- 不应简单压缩到文字无法阅读。

具体断点在实现阶段用真实内容测试后确定。

---

## 20. AI 与行程修改

AI 是行程页的调整能力，而不是独立信息孤岛。

用户可以提出：

- “第二天少走一点。”
- “把富士山放到天气最好的一天。”
- “三天都不要换酒店。”
- “保留这个预约，其他重新排。”
- “午饭控制在 1 小时以内。”

AI 应：

1. 读取结构化 Trip State。
2. 转换用户意图为设置变化。
3. 判断哪些节点被锁定。
4. 重新计算受影响部分。
5. 同步地图、底部栏、方案区。
6. 给出变更摘要。

---

## 21. 信息单一事实源

地图、底部栏、方案区、设置、AI 不得各维护一份独立行程数据。

统一：

```text
Trip State
 ├─ Map View
 ├─ Day / 3-Day / All-Day Range View
 ├─ Bottom Execution Panel
 ├─ Recommendation Panel
 ├─ Settings / Popover
 └─ AI Context
```

任何视图修改都必须回写同一个 Trip State。

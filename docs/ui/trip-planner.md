# 1. 页面定位

Planner 是 TravelAssist 的核心旅行工作台。

三个区域职责严格分离：

```text
地图
= 空间：在哪里、路线怎么走、周边有什么

右侧控制面板
= 决策：和谁去、什么时候去、偏好是什么、当前用哪个方案

底部执行面板
= 时间：几点做什么、持续多久、移动多久、哪一天更累
```

核心目标不是让用户在多个表单页之间跳转，而是让：

- 地图；
- 行程；
- 偏好；
- 预约；
- AI 判断；
- 方案比较；

在一个沉浸式工作区中联动。

# 2. 整体布局

宽屏桌面以 16:9 为主要设计基准。

```text
┌──────────────────────────────────────────────────────────────┐
│ 顶部导航                                                     │
├──────────────────────────────────────────────┬───────────────┤
│                                              │               │
│                 地图工作区                   │   右侧栏      │
│                   ≈ 75%                      │    ≈ 25%       │
│                                              │               │
│ 左侧地图工具         日程范围选择器            │ 上半：设置 50% │
│                                              ├───────────────┤
│ 地图 / Pin / 区域 / 路线 / 详情展开            │ 下半：方案 50% │
│                                              │               │
├──────────────────────────────────────────────┤               │
│             底部执行面板 ≈ 页面高度 25%        │               │
│ 行程｜移动｜预约票务｜天气备选｜住宿餐饮｜详细 │               │
└──────────────────────────────────────────────┴───────────────┘
```

## 2.1 冻结比例

- 左侧地图工作区：约 `75%` 页面宽度；
- 右侧控制面板：约 `25%` 页面宽度；
- 右侧栏视觉上不得接近 `1/3`；
- 右侧栏从 Header 下方一直到底部；
- 右侧栏上半 / 下半约 `1 : 1`；
- 上下两区紧贴，是同一个连续容器；
- 底部栏只覆盖左侧工作区；
- 底部栏默认约 `24%–26%` 页面高度。

# 3. 视觉语言

整体色调以已经确认的账户 / Personal Center 页面为基准。

## 3.1 色彩

主色：

- 暖白；
- 象牙白；
- 极淡樱花粉；
- 暖米灰；
- 深蓝灰 / 墨色文字；
- 珊瑚红作为主强调。

原则：

> **除行程路线和少量状态语义外，不使用大量不同色彩。**

地图路线可以承担主要颜色表达；其他：

- 图标；
- 卡片；
- Tab；
- Pin 外框；
- 状态标签；

尽量低饱和。

## 3.2 卡片

- 大圆角；
- 轻阴影；
- 低对比边框；
- 轻微半透明；
- 像镶嵌在地图上的浮层；
- 不使用强玻璃拟态；
- 不做 SaaS Dashboard / OTA 列表风。

## 3.3 Header

正式 Planner Header 比当前工程化版本更有产品感：

- 高度约 `60–68px`；
- 左：TravelAssist Logo；
- 中：探索目的地 / AI 行程规划 / 旅行灵感 / 实用工具；
- 右：搜索、通知、头像；
- 不堆过多次级信息。

# 4. 地图主区域

地图是页面第一视觉主体。

## 4.1 地图左上角

**不显示大型行程概览。**

不得放：

- 行程名称大卡；
- 旅行封面；
- 日期摘要；
- 天气摘要；
- 同行人摘要。

这些信息由右栏和底栏承担。

## 4.2 地图底图

地图风格：

- 降低 POI 杂讯；
- 暖色 / 低饱和；
- 道路与地名清晰但不抢路线；
- 海面、山地、行政区域有足够层次；
- 避免工程灰白底图成为页面主视觉。

## 4.3 地图必须能表达

- 当前方案路线；
- 每日路线；
- 景点；
- 活动；
- 已确定餐厅；
- 已确定酒店；
- 推荐美食区；
- 推荐住宿区；
- 交通节点；
- 预约状态；
- 前后相邻日期的上下文路线；
- 当前定位；
- 路线段交通方式与耗时。

# 7. 1日选择器

默认按钮可以显示：

```text
1日
```

点击后切换为：

```text
第 N 天 ▼
```

不使用大面积长下拉。

## 7.1 快速选择

打开后优先显示：

```text
[1] [2] [3] [输入]
```

行程较长时：

- 快捷按钮可显示当前附近的若干 Day；
- `输入` 允许直接填数字；
- 仍可通过标准下拉 / 列表访问全部天数。

例如用户当前在第 8 天：

```text
[7] [8] [9] [输入]
```

## 7.2 切换结果

选择 Day 后：

- 地图突出该日；
- 底部进入该日模式；
- 当前方案不变化；
- 右侧设置不变化；
- 当前底部 Tab 尽量保持；
- 地图自动调整到合理视野。

# 8. 3日选择器

点击 `3日` 后显示紧凑形式：

```text
从第 N 天开始 ▼
```

不在常驻按钮中写完整“从第 N 天开始的 3 天”。

## 8.1 快速选择

例如：

```text
[1] [2] [3] [输入]
```

含义：

- 从第 1 天开始的 3 天；
- 从第 2 天开始的 3 天；
- 从第 3 天开始的 3 天。

只生成有效窗口：

```text
总天数 5 天：
1–3
2–4
3–5
```

不得生成：

```text
4–6
5–7
```

## 8.2 三日切换结果

- 地图显示连续 3 天；
- 底部切换为三日比较模式；
- 自动覆盖三天空间范围；
- 当前方案仍不变化。

# 10. 非当前日期路线规则

不把其他所有日期都铺成灰线。

冻结：

> **当前范围 = 主信息；前后相邻范围 = 浅灰上下文；其他 = 隐藏。**

## 10.1 1日

查看 D5：

```text
D4 最后节点 ─浅灰→ D5 起点
D5 正式路线
D5 终点 ─浅灰→ D6 第一节点
```

## 10.2 3日

查看 D4–D6：

```text
D3 → D4  浅灰
D4–D6    正常
D6 → D7  浅灰
```

## 10.3 灰线

- opacity：约 20%–30%；
- line width：主线路约 60%–70%；
- 不显示普通景点编号；
- 不显示细碎交通图标。

- 圆形图片或图标；

- 名称标签；
- 选中态边框加强；

## 12.2 推荐景点


# 13. Pin / 区域详情展开动画

地图点开后不使用普通突然出现的 Popup。

冻结交互：

> **小圆形 → 快速放大 → Morph 成圆角长方形信息卡。**

## 13.1 展开阶段

1. 点击反馈：80–120ms；
2. 圆点放大至约 1.15–1.25 倍：100–140ms；
3. 形状向上 / 右上展开成圆角矩形：160–220ms；
4. 内容渐入 + 上浮 4–8px：80–140ms；
5. 当前对象相关路线加强，其他对象轻微降噪。

## 13.2 收起

触发：

- 点击地图空白；
- 点击其他对象；
- 卡片关闭；
- Esc。

动画：

1. 内容淡出；
2. 卡片缩回胶囊；
3. 缩回圆点；
4. 地图其余对象恢复。

总收起时间建议约 220–280ms 内。

## 13.3 性能原则

动画优先使用：

- transform；
- opacity；
- clip / border-radius；
- 少量尺寸插值。

不为这一动画引入大型动画库。

# 15. 正式景点 / 活动快速卡

至少显示：

## 顶部
- 名称；
- 类型；
- 图片；
- 关闭。

## 时间
- Day；
- 开始时间；
- 当前持续时间；
- 建议持续时间。

## 状态
示例：

- `√ 已预约`
- `√ 已订票`
- `已加入行程`
- `必去`
- `! 时间较紧`
- `! 建议提前`
- `!! 可能冲突`
- `待确认`

## AI 判断
只显示最重要的 2–3 条：

- 与上一站衔接顺畅；
- 当前停留偏短，建议增加 20 分钟；
- 固定预约，不建议后移；
- 当前天气更适合上午；
- 对儿童 / 老人强度偏高。

## 前后交通
例如：

```text
上一站 → 当前：电车 18 分钟
当前 → 下一站：步行 12 分钟
```

## 基础信息
按需：

- 开放时间；
- 门票；
- 是否预约；
- 排队风险；
- 雨天友好度。

## 操作
- 调整时间；
- 替换；
- 查看附近；
- 标记必去；
- 锁定；
- 从行程移除；
- 询问 AI；
- 查看详细。

1. 图片与基础信息；
2. 为什么推荐；

- 显示入住时间；
- 显示预约状态。

右侧方案：

# 21. 预约状态属于行程节点

预约不是独立于行程的一张清单。

冻结：

> **预约 = Trip Item 的状态。**

典型流程：

```text
地图推荐
→ 加入当前方案
→ 底部立即出现具体节点
→ 待预约 / 待购票
→ 完成预约
→ Map / Bottom / Booking Tab / Right Panel 同步
```

固定时间预约默认：

```text
fixedTime = true
```

重新规划时保护，除非用户明确允许修改。

---

# 22. 预约状态语义

推荐：

```text
not_required
pending
booking
booked
ticketed
pay_on_site
failed
cancelled
changed
```

UI 标签：

## 正常 / 已完成

# 45. 一日模式：时间比例行程条

这是底部行程的核心表现。

## 45.1 时间范围

先计算：

```text
dayStart = 当天最早行程开始时间
dayEnd   = 当天最晚行程结束时间
daySpan  = dayEnd - dayStart
```

例如：

```text
08:00 → 20:00
总跨度 = 12小时
```

整个可用横向宽度代表这 12 小时。

## 45.2 块位置

活动开始位置：

```text
x = (itemStart - dayStart) / daySpan
```

活动宽度：

```text
width = itemDuration / daySpan
```

例如景点 40 分钟：

```text
40分钟 / 720分钟
≈ 5.56%
```

原则上占整个时间带约 5.56%。

实际 UI 可设置最小可读宽度，但：

- 几何比例仍应尽量保留；
- 最小宽度不得误导为更长真实时长；
- hover / 展开时显示准确时间。

# 51. 三日模式：共同时间尺度

为了真正比较轻松 / 辛苦程度，三天必须使用**共同横轴**。

```text

compareEnd   = 三天最晚的 dayEnd

```

例如：

```text

```

- Day 2 的第一块自然比 Day 1 更靠右；
- 用户可以直接看出哪天早出；
- 晚结束的 Day 也会明显更长。

# 61. 状态色与类别色

视觉仍以低饱和为主。

## 状态
绿色：
- 已预约；
- 已订票；
- 已确认。

黄色：
- 时间较紧；
- 排队风险；
- 建议提前。

红色：
- 冲突；
- 来不及；
- 高风险。

灰 / 蓝灰：
- 推荐；
- 备选；
- 信息。

## 时间条类别
建议最多 4–5 个轻量类别色：

- 景点 / 活动；
- 移动；
- 餐饮；
- 住宿；
- 空白 / 缓冲。

不可因为类别增加让页面回到多彩杂乱状态。

# 62. AI 分析的呈现规则

AI 不应占大面积聊天框。

优先嵌入：

- 行程块状态；
- 地图详情卡；
- 三日比较摘要；
- 重新规划变化摘要。

AI 判断分为：

```text
正常
需确认
有问题
```

视觉：

- 正常：√ / 正常文本；
- 需确认：黄色 `!`；
- 有问题：红色 `!` / `!!`。

不依赖颜色作为唯一表达。

---

# 63. 重新规划与锁定

以下默认不可被自动移动：

- fixedTime 预约；
- 用户标记必去且锁定；
- 已确认酒店；
- 已购买长途交通；
- 用户显式锁定时间。

重新规划后必须提供：

```text
改了什么
为什么改
哪些没动
```

用户确认后再正式应用重要变更。

# 64. 预约 Provider 边界

地图详情可显示：

- 官方；
- Booking / Agoda 等住宿渠道；
- TableCheck / OpenTable / 官网等餐饮渠道；
- 官方票务 / Klook / GetYourGuide / Viator 等景点渠道。

同一酒店必须先归并到 TravelAssist Canonical Hotel，再列价格渠道，不能在地图上重复成多个酒店。

前端通过统一 Provider Gateway 消费，不直接理解每个第三方 API。

MVP 不通过爬虫伪造实时价格 / 桌位。

# 65. Mapbox 技术边界

Mapbox 负责：

- 底图；
- 坐标；
- 地图渲染；
- GeoJSON；
- 道路空间能力；
- 后续 walking / driving / cycling 等。

TravelAssist 负责：

- Day；
- 行程顺序；
- 推荐；
- 预约；
- 当前方案；
- 住宿 / 餐饮区域；
- AI 判断。

地图优先：

```text
GeoJSON Source
+ Mapbox Style Layer
```

少量需要 DOM Morph 的详情卡使用 Overlay / Popup 层。

切换：

```text
1日 → 3日 → 全日
```

只切 View Data，不重新建立 Trip 数据，不无意义重算路线。

# 66. 单一事实源

统一：

```text
Trip State
├─ Map
├─ Range Selector
├─ Right Settings
├─ Recommendations
├─ Bottom Timeline
├─ Booking
└─ AI Context
```

所有视图共享：

```text
tripItemId
```

不得维护：

```text
地图行程
底栏行程
AI行程
右栏行程
```

四份独立数据。

- Keyboard；

# 70. 后续实现验收重点

下一轮 Planner 实现 / 精修时，优先验证：

1. 右侧同行人 4 类与 Step 3 数据结构是否统一；
2. 出发 / 返回日期区间是否影响 Day / 住宿；
3. 三类核心偏好三级交互是否清晰；
4. 高级设置 Popover 是否无 layout shift；
5. 时间比例行程条是否真实反映时间；
6. 三日比较是否能一眼看出早出、晚归、移动密度和辛苦度；
7. Pin Morph 动画是否顺滑且不遮挡地图；
8. 推荐住宿转确定酒店后的隐藏 / 替换是否正确；
9. Map / Bottom / Right / Booking 是否真正同源；
10. 视觉是否仍保持克制，而不是因状态和类别重新变得杂乱。

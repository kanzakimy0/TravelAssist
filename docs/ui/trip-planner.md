# 行程主页面详细设计

> 状态：v0.3 / 页面布局、核心交互、日程范围地图与底部信息层级已冻结  
> 更新日期：2026-09-05  
> 适用：TravelAssist Web 桌面端行程主页面

## 1. 页面定位

行程主页面是 TravelAssist 的核心旅行工作区。

页面职责按三个区域严格区分：

- **地图 = 空间**：地点、路线、区域关系、交通段、地图图层，以及 1 日 / 3 日 / 全行程三种观察尺度。
- **右侧栏 = 整趟旅行的决策与方案**：同行人、日期、偏好、高级设置、路线重算、方案切换。
- **底部栏 = 时间 + 顺序 + 数据 + 判断**：在 1 日模式负责当天执行，在 3 日模式负责连续几天比较，在全行程模式负责整体结构总览。

设计原则：

1. 地图始终是页面视觉主体。
2. 右侧栏宽度约为页面 **1/4**，不能产生接近 1/3 的视觉重量。
3. 底部信息条高度约为页面 **1/4**。
4. 右侧栏延伸到底部；底部信息条只覆盖地图区域，不进入右侧栏。
5. 页面缩小到指定响应式阈值后：
   - 右侧栏折叠成单一入口按钮；
   - 底部信息条折叠成单一入口按钮。
6. 响应式具体像素断点由实现阶段依据实际内容密度确定；**折叠行为本身已冻结**。
7. `1日 / 3日 / 全日` 不是单纯改变地图缩放，而是改变地图和底部栏的信息颗粒度。

## 2. 整体布局

宽屏桌面端以 16:9 为主要设计基准。

```text
┌──────────────────────────────────────────────────────────────┐
│ 顶部导航                                                     │
├──────────────────────────────────────────────┬───────────────┤
│                                              │               │
│                 地图主区域                   │   右侧栏      │
│                ≈ 页面 3/4                    │  ≈ 页面 1/4   │
│                                              │               │
│ 左侧可隐藏图层栏        日程范围选择器         │ 上半：设置     │
│                                              │               │
│ 路线 / 地点 / 交通 / 区域                    ├───────────────┤
│                                              │ 下半：方案     │
│                                              │               │
├──────────────────────────────────────────────┤               │
│              底部信息条 ≈ 页面高 1/4          │               │
│ 行程｜移动｜预约票务｜天气备选｜住宿餐饮｜详细 │               │
└──────────────────────────────────────────────┴───────────────┘
```

### 2.1 视觉比例

- 地图 + 底部栏所在左侧工作区：约 **75% 页面宽度**。
- 右侧栏：约 **25% 页面宽度**。
- 右侧栏内部：
  - 上半设置区：约 50%；
  - 下半方案区：约 50%；
  - 两部分必须**紧贴、连续、属于同一个右侧容器**，不要做成上下相距很远的独立卡片。
- 底部栏：约 **25% 页面高度**，覆盖左侧地图工作区。

## 3. 视觉风格

整体色调以当前账户页面设计为准。

### 3.1 色彩

- 主背景：暖白、象牙白、低饱和米色。
- 辅助装饰：非常淡的樱花粉 / 暖粉。
- 正文：深蓝灰 / 深墨色。
- 边框：低对比暖灰粉。
- 强调按钮：克制的珊瑚粉 / 暖红。
- **除行程路线外，不使用大量高饱和颜色。**
- 地图 Pin、功能图标、状态标签均应减少无必要的多色混用。

### 3.2 卡片

- 大圆角。
- 轻阴影。
- 轻微半透明 / 镶嵌在地图上的感觉。
- 不使用强烈玻璃拟态。
- 卡片之间间距紧凑但不拥挤。

### 3.3 地图路线

路线是页面中允许保留较明显色彩对比的主要元素。

- 当前查看路线可使用明确主色。
- 多日路线需要区分时，颜色数量应克制。
- 不依赖颜色作为唯一识别方式，同时使用 Day / 日期 / 节点标签。
- 非当前选择范围的上下文路线使用浅灰弱化，不与正式路线争夺视觉注意力。

## 4. 地图主区域

地图负责空间关系，不负责重复展示旅行摘要。

### 4.1 左上角

**不显示行程概览卡。**

删除：

- 行程名称大卡片
- 日期摘要
- 天气摘要
- 同行人摘要
- 目的地封面

这些信息已在右侧栏与底部栏中存在，不得重复占用地图面积。

### 4.2 地图可展示内容

地图根据当前时间范围动态展示：

- 当前方案路线
- 每日路线 / 跨日路线 / 跨城路线
- 景点 Pin
- 住宿 / 住宿区域
- 餐饮区域
- 交通节点
- 已预约活动
- 推荐区域
- 当前定位
- 路线段交通方式与时间

景点选中后可显示小型地点卡，但不得恢复成左上角大型行程概览。

---

## 5. 左侧地图图层栏

地图左侧保留快速图层 / 分类工具栏。

建议项目：

- 图层
- 景点
- 交通
- 酒店 / 住宿
- 餐饮
- 已订 / 已预约活动
- 更多
- 当前定位（如需要）

### 5.1 收起与展开

左侧栏必须支持手动隐藏：

- 展开：显示图标 + 文字。
- 收起：只保留一个小型展开按钮。
- 收起后地图获得完整空间。
- 再次点击恢复。

该栏属于地图工具，不属于行程设置。

---

## 6. 地图日程范围选择器

在**地图最右侧、右侧栏左边**设置一个紧凑的日程范围选择器。

基础模式：

- `1日`
- `3日`
- `全日`

其中“全日”在产品语义上等于“全行程模式”。

### 6.1 选择 1 日

点击 `1日` 后，原 `1日` 按钮变成当天选择下拉菜单。

示例：

```text
第1天 ▼
3日
全日
```

下拉内容：

- 第1天
- 第2天
- 第3天
- ...
- 第N天

用户选择某一天后：

- 地图突出该天正式路线；
- 底部栏同步到该天；
- 地图自动调整到当天主要路线与地点均可理解的视野。

### 6.2 选择 3 日

点击 `3日` 后，原 `3日` 控件变成：

```text
从第1天开始的3天 ▼
```

或等价紧凑文案：

```text
Day 1–3 ▼
```

下拉内容根据行程总天数动态生成有效连续 3 天区间。

用户切换后：

- 地图同时显示连续 3 天正式路线；
- 自动调整地图视野覆盖这 3 天；
- 底部栏同步对应 3 天的时间范围。

### 6.3 选择全日

点击 `全日`：

- 显示完整旅行的城市 / 主要区域与长距离路线；
- 自动适配整趟行程地图边界；
- 不显示起始日下拉菜单；
- 底部栏切换为全行程结构视图。

### 6.4 切换范围时保持不变的状态

切换 `1日 / 3日 / 全日` 时：

- 当前推荐方案不变化；
- 右侧栏设置状态不变化；
- 底部栏当前一级 Tab 尽量保持不变；
- 不刷新整个页面；
- 地图平滑调整视野。

只改变：

1. 地图视野；
2. 地图信息密度；
3. Pin 层级；
4. 路线颗粒度；
5. 底部栏内容颗粒度。

## 7. 1 日 / 3 日 / 全行程地图内容规则

三种模式对应三个不同任务：

- **1日 = 执行模式**：今天具体怎么走。
- **3日 = 调整模式**：连续几天之间是否合理。
- **全行程 = 规划模式**：整趟旅行的空间结构是否合理。

### 7.1 1 日模式

核心问题：

> 今天从哪里出发、按什么顺序去哪里、怎么移动、在哪里吃饭、晚上住哪里。

#### 默认视野

自动包含当天：

- 起点；
- 全部正式景点 / 活动；
- 主要路线；
- 餐饮区域；
- 当晚住宿。

如果当天存在跨城 / 长距离移动，则自动扩大视野。

#### 必须显示

- 当日连续主路线；
- 景点 / 活动顺序编号；
- 起点与终点；
- 交通方式图标；
- 当晚酒店或推荐住宿区域；
- 午餐 / 晚餐推荐区域；
- 已确认餐厅；
- 已预约活动；
- 最多约 3–5 个顺路 / 备选 / 雨天替代地点。

正式节点可使用象征性缩略图，例如：

- 道顿堀 → 霓虹街景；
- 海游馆 → 鲸鲨；
- 清水寺 → 寺庙轮廓。

默认隐藏：

- 非相关日期普通景点；
- 非相关日期完整路线；
- 大量候选餐厅 / 酒店；
- 无关 POI。

### 7.2 3 日模式

核心问题：

> 这三天分别在哪些区域活动、每天怎么衔接、住宿是否合理、是否明显折返。

#### 默认视野

自动包含连续 3 天：

- 每日主要活动区域；
- 每日核心景点；
- 每日住宿；
- 跨日移动；
- 跨城路线。

#### 日期识别

地图节点使用所属日期标识，例如：

- `D4 · 清水寺`
- `D5 · 岚山`
- `D6 · 金泽站`

#### 必须显示

- 每日主路线，不展开所有小段步行 / 换乘；
- 每日活动范围；
- 每日最多约 3–4 个核心地点；
- 住宿及连住天数；
- 换酒店；
- 长距离铁路 / 自驾 / 飞机 / 渡轮等跨日交通；
- 住宿区域变化。

可显示轻量 3 日摘要：

- 总移动量；
- 换住宿次数；
- 最忙一天；
- 最长移动段。

### 7.3 全行程模式

核心问题：

> 整趟旅行去了哪些城市、顺序是否合理、哪里停留时间长、有没有明显绕路。

#### 默认视野

自动缩放至完整旅行范围，例如：

```text
东京 → 箱根 → 京都 → 大阪 → 广岛
```

#### 必须显示

- 城市 / 主要区域节点；
- 城市间主要路线；
- 飞机 / 新干线 / 铁路 / 自驾 / 渡轮等长距离交通；
- 每个城市停留天数 / 晚数；
- 全程住宿结构；
- 抵达 / 离境机场；
- 长距离车站；
- 租车 / 还车点；
- 重要港口；
- 长行程时的国家 / 大区域分组。

默认隐藏：

- 普通景点；
- 普通餐厅；
- 午晚餐推荐区；
- 市内公交 / 地铁 / 步行；
- 临时候选 POI。

### 7.4 三种模式地图内容对比

| 内容 | 1日 | 3日 | 全行程 |
|---|---:|---:|---:|
| 当日详细路线 | ◎ | △ | × |
| 步行路线 | ◎ | × | × |
| 市内交通 | ◎ | 简化 | × |
| 跨城交通 | ◎ | ◎ | ◎ |
| 正式景点 | ◎ | 核心地点 | × |
| 午 / 晚餐区域 | ◎ | 摘要 | × |
| 酒店 | ◎ | ◎ | 城市级摘要 |
| 住宿区域 | ◎ | ◎ | 简化 |
| 推荐备选景点 | ◎ | 少量 | × |
| 每日活动范围 | △ | ◎ | × |
| 城市节点 | △ | ◎ | ◎ |
| 国家 / 大区域 | × | △ | ◎ |

## 8. 非选择日期路线的灰线规则

**非选择日期不是全部铺成灰色。**

设计原则：

> 选中范围 = 主信息；相邻范围 = 灰色上下文；其他范围 = 隐藏。

### 8.1 1 日模式

例如正在查看第 5 天：

```text
第4天终点 ─灰→ 第5天起点 → 第5天正式路线 → 第5天终点 ─灰→ 第6天起点
```

只保留：

- 前一天最后节点 → 当前日首节点；
- 当前日最后节点 → 后一天首节点。

其他日期路线隐藏。

非选择日期普通景点 Pin 不随路线一起全部灰显，仅在需要表达衔接时保留前 / 后相邻节点。

### 8.2 3 日模式

例如选择 D4–D6：

- D4 / D5 / D6 正常显示；
- D3 → D4 的直接衔接线路浅灰；
- D6 → D7 的直接衔接线路浅灰；
- 其他日期路线隐藏。

### 8.3 全行程模式

全行程的城市级 / 长距离主线全部正常显示，不使用“非选择日期灰线”。

### 8.4 灰线视觉参考

灰色上下文路线的目标视觉强度：

- 不透明度约 **20%–30%**；
- 线宽约为正式路线的 **60%–70%**；
- 不显示细分交通图标；
- 不显示普通景点编号；
- 默认不突出；
- 悬停后允许轻微增强。

这些数值作为实现参考范围，最终视觉可在真实地图底图上微调，但“只显示相邻上下文、其他隐藏”的规则已冻结。

右侧栏固定为页面约 **1/4 宽度**，并延伸到页面底部。

不再设置顶部：

- `详细设置`
- `行程方案`

两种页签。

用户直接看到设置与方案。

## 10. 右侧栏上半部分：旅行设置

### 10.1 第一排：同行人与旅行日期

两个并排选项卡。

#### 同行人

摘要示例：

- 2位成人
- 2成人 · 1儿童
- 家庭

#### 旅行日期

摘要示例：

- 4月10日–4月12日
- 3天2晚

### 10.2 第二排：三类核心偏好

三个并排选项卡。

#### 景点偏好

摘要：自然风光 / 经典地标 / 摄影等。

#### 餐饮偏好

摘要：当地美食 / 日料 / 咖啡甜品等。

#### 住宿偏好

摘要：舒适型 / 靠近车站 / 温泉酒店等。

详细内容点击卡片后再编辑，不在默认状态全部铺开。

## 11. 更多行程设置

### 11.1 默认状态

`更多行程设置` 默认**不展开**。

与 `重新生成路线` 放在同一行。

布局原则：

- 两个按钮同一高度、同一视觉等级；
- `更多行程设置` 可略宽；
- `重新生成路线` 位于右侧，必须始终存在；
- 两者整体保持接近 1:1，不可让其中一个明显过小。

### 11.2 点击行为

点击 `更多行程设置` 后：

- 在按钮原位置附近弹出 Popover / 浮动菜单；
- 浮层覆盖在当前页面之上；
- **不得撑开右侧栏；**
- **不得推动推荐方案向下移动；**
- **不得改变地图、底部栏或整个页面布局。**

再次点击、点击关闭按钮或点击浮层外部即可关闭。

### 11.3 浮层内容

包含：

- 预算
- 旅行节奏
- 移动偏好
- 时间偏好
- 拥挤与排队
- 摄影与观景
- 已预约活动
- 特殊需求
- 行李设置
- 天气策略
- 方案约束
- 更多筛选

浮层顶部优先并排：

#### 预算

- 主值：中等预算
- 小字：¥15,000–25,000 / 人 / 天

#### 旅行节奏

- 主值：偏轻松
- 小字：每天 2–4 个主要地点

## 12. 重新生成路线

`重新生成路线` 位于 `更多行程设置` 右侧。

点击逻辑：

1. 读取当前同行人、日期、三类偏好以及高级设置。
2. 保留明确锁定的预约 / 必去点 / 不可修改条件。
3. 重新计算路线与每天节奏。
4. 生成新的推荐方案或更新当前方案。
5. 同步更新地图、底部栏与右侧方案区。
6. 向用户展示变化摘要，避免无说明直接替换。

---

## 13. 右侧栏下半部分：推荐方案

下半部分与上半部分约 **1:1 面积**。

方案区固定采用 **3 个横向方案条**，上下排列：

```text
方案1  东京·富士山经典之旅       >
方案2  深度体验之旅              >
方案3  轻松休闲之旅              >
```

### 13.1 当前方案

当前选中方案必须有：

- 完整外框；
- 低饱和强调边框；
- `当前方案` 或 `已选中` 小字标签；
- 方案名称；
- 关键差异标签；
- 必要的简短指标。

当前方案不得只依靠背景颜色区分。

### 13.2 其他方案

方案 2、方案 3 使用同尺寸横条：

- 缩略图；
- 方案编号；
- 方案名称；
- 一句核心差异 / 若干紧凑标签；
- 进入 / 切换箭头。

点击后：

- 该方案成为当前方案；
- 外框和 `当前方案` 标签同步切换；
- 地图和底部栏同时更新。

---

## 14. 底部信息条总体规则

底部信息条覆盖地图区域，默认高度约 **页面高度的 1/4**。

底部栏保持同一套外框和一级 Tab，不因为时间范围切换而改变整体结构。

从左到右固定为：

1. **行程**
2. **移动**
3. **预约·票务**
4. **天气·备选**
5. **住宿·餐饮**
6. **详细**

`行程` 为默认打开项。

切换 `1日 / 3日 / 全日` 时：

- 一级 Tab 数量与位置不变；
- 信息栏高度原则上不变；
- 当前 Tab 尽量保留；
- 仅改变 Tab 内部的数据颗粒度和卡片结构。

底部栏三种定位：

- **1日：今天怎么执行。**
- **3日：这几天怎么安排更合理。**
- **全行程：整趟旅行结构是否合理。**

## 15. 1 日模式下的底部信息栏

1 日模式为**执行型信息栏**，信息颗粒度最细。

### 15.1 行程

默认主体为当天详细时间轴，例如：

```text
08:30 酒店出发
09:10–11:00 清水寺
11:15–12:00 二年坂
12:10–13:10 午餐区域
13:40–15:20 祇园
16:00–17:30 锦市场
18:30 晚餐区域
20:00 返回酒店
```

每段至少可显示：

- 时间；
- 地点；
- 停留时长；
- 交通方式；
- 移动时间；
- 是否预约；
- 是否可调整。

### 15.2 移动

显示当天全部主要移动段，可进一步展开：

- 驾车；
- 火车 / 电车；
- 公交；
- 步行；
- 渡轮；
- 停车；
- 换乘；
- 总耗时；
- 距离；
- 通票 / 道路等必要提示。

### 15.3 预约·票务

显示：

- 固定时段景点；
- 导览预约；
- 门票；
- 餐厅预约；
- 城市卡 / 通票；
- 演出；
- 酒店固定入住条件；
- 已购 / 待购；
- 报到提前量；
- 取消截止时间。

### 15.4 天气·备选

显示：

- 当天天气；
- 天气风险；
- 日出 / 日落；
- 山区能见度；
- 强风 / 降雪 / 高温等；
- 雨天路线；
- 室内备选；
- 天气变化后的路线替代方案。

### 15.5 住宿·餐饮

住宿显示：

- 今晚酒店 / 推荐住宿区域；
- 入住时间；
- 停车；
- 联系方式；
- 订单入口；
- 明早退房；
- 次日出发便利性。

餐饮显示：

- 午餐时间 / 区域；
- 晚餐时间 / 区域；
- 已预约餐厅；
- 候选餐厅；
- 价格层级；
- 与当前路线的关系。

### 15.6 详细

1 日模式的 `详细` 主要显示当天执行数据和深层信息：

- 当日总移动时间；
- 总步行距离；
- 景点数量；
- 营业时间风险；
- 天气影响；
- 体力强度；
- 费用明细 / 预算估算；
- 地址 / 联系方式；
- 行李信息；
- 停车 / 租车；
- 儿童 / 老人 / 无障碍提醒；
- AI 对当天安排的解释。

## 16. 3 日模式下的底部信息栏

3 日模式为**比较 / 调整型信息栏**。

不把 3 天所有小时级细节全部铺开。

### 16.1 行程

默认主体变成 **3 个日程块**。

例如：

```text
D4  京都东山      4个核心地点 · 约7小时 · 高强度
D5  岚山          3个核心地点 · 约6小时 · 中强度
D6  京都 → 金泽   跨城移动 · 换酒店
```

点击某一天：

- 对应日程块展开；
- 地图突出该天路线；
- 其他两天保持摘要；
- 提供“查看第 X 天详细行程”，可进入 1 日模式。

### 16.2 移动

3 日模式重点显示：

- 每天主要交通结构；
- 每日总移动量；
- 跨日移动；
- 跨城市移动；
- 长距离交通；
- 换酒店路线。

隐藏普通 5 分钟步行、小换乘等细碎信息。

### 16.3 预约·票务

按天归纳 3 天内重要预约：

- 固定时间预约；
- 已购票活动；
- 跨城交通票；
- 需要提前报到 / 入场的项目；
- 预约冲突或时间风险。

### 16.4 天气·备选

比较 3 天天气与日程适配关系：

- 哪一天更适合户外；
- 哪一天适合室内；
- 是否建议互换 D4 / D5；
- 雨天替代方案影响。

### 16.5 住宿·餐饮

住宿重点显示：

- 每晚住哪里；
- 是否连续住宿；
- 是否换酒店；
- 换酒店是否产生额外移动。

餐饮以日为单位显示：

- 午餐推荐区域；
- 晚餐推荐区域；
- 已预约的重点餐厅。

不默认铺开全部候选餐厅。

### 16.6 详细

3 日模式的 `详细` 为 3 日整体分析：

- 3 天总移动时间；
- 总步行量；
- 每日强度；
- 最忙 / 最松一天；
- 换住宿次数；
- 跨城次数；
- 明显折返；
- 时间 / 预约冲突；
- 天气与三天安排匹配度；
- AI 调整建议。

示例：

> 将 D5 与 D4 调换，可减少约 35 分钟移动，并把主要户外活动放到天气更好的一天。

## 17. 全行程模式下的底部信息栏

全行程模式为**结构 / 总览型信息栏**。

不再以单个景点时间轴为主，而以城市 / 行程段为主。

### 17.1 行程

默认主体变成城市 / 行程段横条，例如：

```text
D1–D4   东京      4天3晚
D5      箱根      1晚
D6–D9   京都      4天3晚
D10–D11 大阪      2天1晚
D12     离境
```

点击某个城市段：

- 地图高亮对应城市 / 区域；
- 显示进入与离开的长距离交通；
- 底部展开该段核心活动、住宿和交通摘要；
- 可进一步进入 3 日或 1 日模式。

### 17.2 移动

全行程只显示主要长距离交通：

- 城市 → 城市；
- 飞机；
- 新干线 / 长途铁路；
- 长途自驾；
- 渡轮；
- 机场 / 长途车站连接。

隐藏市内地铁、公交、步行和短途出租车。

### 17.3 预约·票务

只突出全程结构中重要或固定的项目：

- 国际 / 国内航班；
- 长距离铁路 / 渡轮；
- 重要门票；
- 影响整段行程的固定预约；
- 特别晚餐 / 稀缺预约。

### 17.4 天气·备选

显示全程层面的天气风险与调整价值：

- 连续雨天区间；
- 山区 / 海岛等天气敏感路段；
- 哪个城市段存在天气替换空间；
- 是否需要移动某个户外日。

### 17.5 住宿·餐饮

住宿是全行程核心结构信息，显示：

- 每个城市住宿晚数；
- 总住宿点数量；
- 换酒店次数；
- 连住情况；
- 是否存在频繁 1 晚换酒店。

餐饮只显示重点预约 / 特别体验，普通午晚餐推荐区域默认隐藏。

### 17.6 详细

全行程 `详细` 变成整趟旅行健康检查：

- 总天数；
- 城市数量；
- 国家 / 地区数量；
- 总换酒店次数；
- 总跨城次数；
- 主要长距离交通；
- 最长移动日；
- 最忙连续区间；
- 最松连续区间；
- 是否明显绕路；
- 是否存在城市停留过短；
- 是否连续高强度；
- 总预算区间；
- 交通 / 住宿预算；
- AI 整体结构建议。

## 18. 六个 Tab 在三种时间尺度下的颗粒度

| Tab / 信息 | 1日 | 3日 | 全行程 |
|---|---|---|---|
| 行程主体 | 小时级时间轴 | 3 个日程块 | 城市 / 行程段横条 |
| 景点 | 全部正式景点 | 每日核心景点 | 主题 / 数量摘要 |
| 移动 | 主要市内段 + 细节 | 每日主交通 + 跨日 | 跨城 / 长距离 |
| 步行 | 显示 | 汇总 | 隐藏 |
| 预约·票务 | 当天全部重要项目 | 3 天重要项目 / 冲突 | 全程结构性预约 |
| 天气·备选 | 当天执行风险 | 3 天比较 / 调换 | 全程天气敏感段 |
| 午晚餐 | 具体时间 / 区域 / 餐厅 | 每日区域 / 重点预约 | 仅重点预约 |
| 住宿 | 当晚详细 | 3 天住宿衔接 | 全程住宿结构 |
| 推荐地点 | 显示 | 少量 | 隐藏 |
| 详细 | 当天执行深度 | 3 天比较分析 | 全程健康检查 |
| AI 建议 | 今天怎么调 | 哪天互换 / 减负 | 整体路线优化 |

## 19. 地图与底部栏双向联动

### 19.1 点击底部栏 → 地图

点击时间轴 / 日程块 / 城市段 / 地点：

- 地图自动定位；
- 对应 Pin / 区域高亮；
- 对应路线高亮；
- 必要时调整地图视野。

### 19.2 点击地图 → 底部栏

点击地图节点：

- 底部栏自动找到对应数据；
- 对应卡片 / 时间轴节点高亮；
- 必要时自动滚动到该项目。

### 19.3 切换时间尺度

切换 `1日 / 3日 / 全日` 时：

- 保留当前推荐方案；
- 保留右侧栏设置状态；
- 底部栏尽量保留当前 Tab；
- 地图与底部栏同时切换信息颗粒度。

视觉语言保持一致：圆角、字体层级、图标、选中效果、悬停效果和展开方式统一。

## 20. 底部栏响应式折叠

当页面宽度或可用地图高度低于指定阈值：

- 底部栏整体折叠成一个小型按钮；
- 地图释放垂直空间；
- 点击按钮以浮层 / 抽屉方式重新展开底部内容；
- 不应简单压缩到文字无法阅读。

具体断点在实现阶段用真实内容测试后确定。

## 21. AI 与行程修改

AI 是行程页的调整能力，而不是独立信息孤岛。

用户可以提出：

- “第二天少走一点。”
- “把富士山放到天气最好的一天。”
- “三天都不要换酒店。”
- “保留这个预约，其他重新排。”
- “午饭控制在 1 小时以内。”

AI 应：

1. 读取结构化 Trip State。
2. 转换用户意图为设置变化。
3. 判断哪些节点被锁定。
4. 重新计算受影响部分。
5. 同步地图、底部栏、方案区。
6. 给出变更摘要。

在 3 日 / 全行程模式下，AI 应优先给出范围级优化建议，而不是把所有当天细节直接铺开。

## 22. 信息单一事实源

地图、底部栏、方案区、设置、AI 不得各维护一份独立行程数据。

统一：

```text
Trip State
 ├─ Map View
 ├─ Day / 3-Day / All-Day Range View
 ├─ Bottom Information Panel
 ├─ Recommendation Panel
 ├─ Settings / Popover
 └─ AI Context
```

任何视图修改都必须回写同一个 Trip State。

时间尺度只改变视图层的聚合方式，不能生成三份彼此独立的行程数据。

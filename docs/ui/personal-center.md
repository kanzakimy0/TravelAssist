## 1. 设计目标

个人中心不是传统后台，也不是数据 Dashboard。

它的核心目标是让用户在进入“自己的空间”后，快速完成三件事：

1. 看见下一次旅行并继续规划。
2. 管理自己已经保存、规划中、完成或收藏的旅行。
3. 在需要时进入长期偏好、同行人和账户管理。

同时，首页可以提供少量**低干扰的旅行延伸入口**，帮助用户在没有立即需要编辑行程时继续发现旅行灵感、回看收藏内容或探索目的地。

整体体验应保持 TravelAssist 的旅行感：**轻、温暖、让人产生想出发的心情**，同时保持足够清晰的功能层级。

个人中心与主 Planner 的职责边界：

```text
Planner
= 这一次旅行怎么安排

Personal Center
= 我的长期资料、长期偏好、同行人和旅行资产
```

## 2. 最终一级 Information Architecture

个人中心冻结为 5 个一级入口：

```text
Personal Center
│
├── 我的首页 Home
├── 我的旅行 Trips
├── 旅行偏好 Preferences
├── 同行人 Companions
└── 账户 Account
```

> 首页新增的“更多功能模块”属于 **Home 内的二级入口区**，**不增加新的一级导航项**。

### 2.1 我的首页 Home

默认落点。

首页只承担“回来以后下一步做什么”，不承担完整管理功能。

首页显示：

- 下一次旅行 Hero
- 我的旅行摘要
- 更多功能模块
- 通知 / 当前用户入口

首页**不显示**：

- 旅行偏好摘要卡片
- 同行人摘要卡片
- 数据统计 Dashboard
- 大量账户设置

> 注意：旅行偏好和同行人只从首页内容区删除，**左侧一级导航入口必须保留**。

### 2.2 我的旅行 Trips

统一承载用户旅行资产：

```text
我的旅行
├── 即将到来
├── 规划中
├── 已完成
├── 收藏
└── 已归档
```

不再把“历史 / 草稿 / 收藏”做成多个一级导航。

建议语义：

- 草稿 → 规划中
- 历史 → 已完成
- 收藏 → 我的旅行中的筛选项

### 2.3 旅行偏好 Preferences

长期偏好管理中心。

继续采用既有“大项目 → 中项目 → 小项目”的渐进设置原则。

主要领域：

- 旅行风格
- 移动 / 交通
- 景点与活动
- 餐饮
- 住宿
- 预算
- 其他 / 高级设置

这里保存长期偏好；Planner 中的本次旅行临时条件不直接覆盖长期偏好。

### 2.4 同行人 Companions

同行人独立为一级入口。

可管理：

- 本人
- 家人
- 儿童 / 婴儿
- 朋友 / 其他同行人
- 移动能力
- 饮食限制
- 兴趣
- 住宿需求
- 无障碍 / 特殊需求

Planner 创建旅行时只负责“这次和谁一起”，并读取个人中心保存的同行人资料。

### 2.5 账户 Account

账户类低频功能统一收纳：

```text
账户
├── 个人资料 Profile
├── 登录与安全 Security
├── 通知 Notifications
├── 数据与隐私 Privacy & Data
└── 帮助 / Legal
```

删除账户、数据导出等危险或低频操作必须放在深层，不进入旅行主导航。

## 3. Desktop 16:9 总体布局

当前正式基准为 Desktop 16:9。

```text
┌──────────────────────────────────────────────────────────────┐
│ 左侧 Personal Sidebar │        右侧 Personal Home            │
│                       │                               🔔 头像  │
│ Logo                  │ ┌──────────────────────────────────┐ │
│ 用户头像 / 名称        │ │ 下一次旅行 Hero                  │ │
│                       │ │ 京都 · 3天2晚                    │ │
│ 我的首页              │ │ 日期 / 同行 / 交通               │ │
│ 我的旅行              │ │ [继续规划]                      │ │
│ 旅行偏好              │ └──────────────────────────────────┘ │
│ 同行人                │                                      │
│ 账户                  │ 我的旅行                    查看全部 →│
│                       │ ┌────────────────┐ ┌───────────────┐ │
│ [日式水彩风景图保留]   │ │ 主旅行大卡片    │ │ 旅行小卡片 1   │ │
│                       │ │                │ ├───────────────┤ │
│                       │ │                │ │ 旅行小卡片 2   │ │
│                       │ └────────────────┘ └───────────────┘ │
│                       │                                      │
│                       │ 更多功能模块                         │
│                       │ [旅行灵感] [我的收藏] [目的地探索]   │
└──────────────────────────────────────────────────────────────┘
```

### 3.1 比例建议

以下为实现参考值，不作为最终像素硬编码：

- Sidebar：约 16%–18% 宽度
- Main：约 82%–84%
- Hero：主内容区顶部约 34%–40% 的首屏高度
- Trips：Hero 下方优先展示 3 张旅行预览卡
- More Features：位于 Trips 下方，首屏空间允许时露出完整一行；空间不足时允许进入首屏下方继续滚动

概念图中的 Trips 可采用 3 张横向卡，也允许后续回到“一大两小”非对称布局；**1.21 冻结的是信息层级，不强制 Trips 卡片必须只有单一网格比例**。最终卡片比例由后续 Shell / Trip Library 设计结合真实数据决定。

## 4. 左侧 Sidebar 设计冻结

左侧栏是个人中心的稳定导航骨架。

### 必须保留

1. TravelAssist Logo / 品牌标志
2. 用户头像
3. 用户名称
4. 简短同步状态
5. 五个一级入口：
   - 我的首页
   - 我的旅行
   - 旅行偏好
   - 同行人
   - 账户
6. **左侧栏底部日式风景插画**

### 左栏底部插画方向

保留已经确认的视觉：

- 水边 / 湖面
- 朱红鸟居
- 远山
- 少量樱花
- 青海波 / 和纸感纹理

插画只作为 Sidebar 底部视觉收尾，不扩散到整个主内容区。

### 当前项状态

当前导航项采用：

- 浅暖底色
- 朱红 / 珊瑚红文字和图标
- 轻量圆角描边
- 不使用厚重大面积纯红填充

## 5. 右侧首页正式布局

### 5.1 顶部全局区

右上仅保留必要的：

- 通知图标
- 当前用户头像
- 下拉入口

不增加额外顶部主导航，避免与左侧一级导航重复。

### 5.2 下一次旅行 Hero

Hero 是首页视觉中心。

信息仅保留：

- `下一次旅行`
- 目的地，例如：京都
- 天数 / 夜数，例如：3天2晚
- 日期
- 同行人数
- 关键移动偏好
- `继续规划` / `查看行程` 主 CTA

不在 Hero 中加入：

- 长段文案
- 装饰性日文句子
- 旅行鸡汤文案
- 统计数字
- 复杂行程明细

#### Hero 图片

必须使用**写实摄影 / 高写实照片风格**。

不使用：

- 水彩景点照片
- 卡通景点
- 手绘城市场景
- 过度梦幻 AI 插画质感

可允许轻度暖色调处理，但需保持真实摄影感。

### 5.3 我的旅行

Hero 下方为“我的旅行”。

首页预览区用于快速回到用户已有旅行，不承担完整筛选和管理功能。

概念基准允许两种排法：

```text
方案 A：三张横向旅行卡
[京都] [大阪] [北海道]

方案 B：一大两小
[主旅行大卡] [小卡1]
               [小卡2]
```

两者共享同一信息优先级：

- 状态
- 目的地
- 天数 / 夜数
- 日期
- 同行人数
- 必要时显示一项交通 / 旅行标签

右上提供：`查看全部 →`

进入完整 `我的旅行` 页面。

### 5.4 更多功能模块 More Features

在“我的旅行”预览下方新增一个轻量二级入口区，标题固定为：

```text
更多功能模块
```

第一版包含 3 个模块：

```text
更多功能模块
├── 旅行灵感 Travel Inspiration
├── 我的收藏 My Favorites
└── 目的地探索 Destination Explore
```

#### 旅行灵感 Travel Inspiration

目标：给用户提供“下一次想去哪 / 可以怎么玩”的轻发现入口。

首页卡片显示：

- 简洁图标
- 标题：旅行灵感
- 一句说明，例如：`为你推荐目的地与玩法`
- 进入箭头

此入口未来可承载：

- 季节旅行推荐
- 主题旅行
- 根据长期偏好生成的灵感
- 热门 / 小众玩法

当前 1.21 只冻结入口位置与语义，不在本 WBS 承诺推荐算法实现。

#### 我的收藏 My Favorites

目标：让用户快速回到已经收藏的旅行内容。

第一阶段优先复用现有 IA：

```text
我的收藏
→ 我的旅行
→ 收藏
```

避免首页再创建一套独立的收藏数据结构。

未来若产品扩展到 POI / 餐厅 / 酒店 / 文章收藏，可继续沿用同一入口，再在收藏中心内分类。

首页卡片显示：

- 简洁图标
- 标题：我的收藏
- 一句说明，例如：`管理你喜欢的目的地与旅行`
- 进入箭头

#### 目的地探索 Destination Explore

目标：提供不以“已有 Trip”为前提的目的地浏览入口。

首页卡片显示：

- 地点 / Pin 图标
- 标题：目的地探索
- 一句说明，例如：`发现更多精彩旅程`
- 进入箭头

未来可进入：

- 国家 / 地区浏览
- 城市目的地页
- 地图探索
- 主题 / 季节目的地推荐

当前 1.21 只冻结首页入口，不冻结完整目的地探索页；若进入正式开发范围，应新增对应 WBS / Task，避免把探索系统隐式塞入个人中心实现。

#### More Features 视觉规则

更多功能模块必须比 Next Trip 和 My Trips 低一级：

- 使用浅色卡片，不使用大幅写实照片作为默认背景
- 可使用非常淡的日本元素剪影 / 水彩装饰
- 每卡只保留图标 + 标题 + 一句说明 + 箭头
- 不显示数据统计
- 不做复杂二级菜单
- Desktop 默认一行 3 卡
- 卡片高度明显低于旅行卡片

目的：让它成为“继续探索”的入口，而不是把个人中心重新变成门户网站。

### 5.5 首页删除项

以下内容**不再出现在个人中心首页正文**：

- 旅行偏好摘要
- 同行人列表 / 同行人卡片

原因：

- 降低首屏信息密度
- 避免首页变成 Dashboard
- 把焦点集中在“下一次旅行”和“我的旅行”

但两者仍保留在左侧一级导航中。

## 6. 背景视觉冻结

最终背景采用已确认的方案 D 延伸方向，但进一步减法。

### 主页面底图

使用：

- 温暖米白 / 象牙白基底
- 非常淡的和纸质感
- 淡粉水彩云雾 / 花瓣感
- 少量青海波纹理
- 非常轻的金粉 / 暖色点缀

### 主页面底图禁止

- **不要放富士山作为大背景**
- 不要大面积鸟居
- 不要寺庙 / 五重塔大背景
- 不要书法 / 中文 / 日文装饰文案
- 不要多组传统日本元素同时抢视觉

原则：

> 日本特色来自“质感、色调和细节”，而不是把所有日本符号同时铺在页面上。

### Sidebar 例外

Sidebar 底部的鸟居风景插画继续保留，因为它被限制在固定区域，不会干扰主内容。

### More Features 例外

更多功能模块允许使用极淡的小型装饰元素，例如：

- 山形水彩剪影
- 鸟居轮廓
- 枫叶 / 樱花局部

但透明度与视觉权重必须低于文字和操作箭头，不能再次形成大背景景观。

## 7. 色调与对比度

基于最终确认稿，整体视觉强度相较上一版高饱和概念稿**降低约 10%**。

### 目标

- 不是灰色 UI
- 不是低饱和极简到没有旅行感
- 保留开心、温暖和旅行期待
- 避免照片、樱花和红色 CTA 同时过艳

### 推荐方向

- 背景：暖米白
- 主强调：朱红 / 珊瑚红
- 辅助：樱粉 / 淡桃色
- 文字：深灰蓝 / 墨色
- Border：极淡暖粉褐
- 图片：写实、自然暖色，不使用 HDR 过强效果

### 临时语义 Token

具体数值仍可在 Design Token WBS 中统一冻结，当前实现应使用语义名：

```text
--pc-bg-canvas
--pc-bg-sidebar
--pc-bg-card
--pc-accent-primary
--pc-accent-soft
--pc-text-primary
--pc-text-secondary
--pc-border-subtle
--pc-nav-active-bg
--pc-nav-active-text
```

不得因为概念图颜色自行建立另一套互不兼容的全局品牌色系统。

## 8. 摄影与插画使用规则

个人中心采用“两种视觉媒介分工”：

### 真实旅行内容

使用**写实照片**：

- Hero 目的地
- 我的旅行卡片
- 旅行详情缩略图

### 品牌与氛围装饰

使用**轻日式水彩 / 和纸插画**：

- Sidebar 底部固定插画
- 页面角落非常轻的背景纹理
- 小型樱花 / 青海波装饰
- More Features 卡片中的低对比度小型装饰

### 禁止混用

不要把旅行照片也画成水彩，因为会让“真实旅行资产”和“装饰层”失去层级差异。

---

## 9. 字体与信息层级

### 目的地 / 大标题

可使用具有一点日式书刊感、但清晰易读的 CJK Serif。

### UI / 控件 / 日期

使用清晰 Sans Serif。

推荐结构：

```text
Hero Destination   大号 Serif / 强标题
Section Heading    中号标题
Card Title         中号或半粗
Body               常规 Sans
Meta / Date        小号 Sans
Button             中等权重 Sans
```

避免把大量正文改成书法字体。

## 10. 交互关系

### 首页

```text
个人中心首页
├── 继续规划 / 查看行程 → Planner 当前 Trip
├── 我的旅行卡片 → Trip 详情 / 继续编辑

├── 旅行偏好 → Preferences
├── 同行人 → Companions
└── 账户 → Account
```

### 头像

右上头像与完整头像菜单行为由 WBS 1.22 详细设计。

### Preferences / Companion Contract

个人中心负责长期数据；Planner 通过公开 Contract 消费：

```text
B Preference Contract → A Planner
B Companion Data → Planner Trip Setup
A Trip Plan Contract → B Saved Trips
```

## 11. 首页信息优先级

从高到低：

1. 下一次旅行
2. 继续规划 / 查看行程
3. 我的旅行
4. 查看全部旅行
5. 更多功能模块
6. 一级导航
7. 通知 / 用户入口

更多功能模块必须保持二级权重，不得抢占 Next Trip 与 My Trips 的视觉焦点。

## 12. Empty State 原则

没有旅行时，首页不能出现大面积空 Dashboard。

建议 Hero 切换为：

```text
下一段旅程，从这里开始
[开始规划]
```

背景仍保持轻日式旅行氛围，但不制造虚假的“下一次旅行”。

我的旅行区显示 1 个轻量 Empty Card 即可。

**更多功能模块在 Empty State 下仍可保留**，因为旅行灵感和目的地探索正好可以成为没有 Trip 时的下一步入口。

推荐 Empty State 下的优先关系：

```text
开始规划
↓
旅行灵感 / 目的地探索
↓
我的收藏
```

详细 Loading / Empty / Error 规范归 WBS 1.29。

## 13. Responsive 边界

本设计书冻结 Desktop IA 和 16:9 首页基准。

### Desktop

使用左 Sidebar + 右内容布局。

More Features 默认 3 卡横排。

### Tablet / Mobile

业务含义保持不变，但不要求机械缩放 Desktop：

- Sidebar 可转 Drawer / Bottom Navigation
- Hero 可变为纵向卡片
- 我的旅行可变为横向滑动或纵向列表
- More Features 可变为 1 列或横向滑动的小卡片组

详细响应式布局归 WBS 1.29。

```text
PersonalCenterLayout

│   ├── BrandMark
```

## 16. Codex / 开发实现约束

1. 以本设计书为 WBS 1.21 的文字基准。
2. Desktop 首先按 16:9 验证。
3. 左侧栏必须保留旅行偏好和同行人一级入口。
4. 左侧栏底部必须预留日式鸟居水景插画区域。
5. 首页正文主信息流为 Next Trip + My Trips + More Features，不显示偏好与同行人摘要。
6. More Features 第一版固定三个入口：旅行灵感 / 我的收藏 / 目的地探索。
7. 我的收藏第一阶段优先复用 `我的旅行 > 收藏`，禁止重复建一套收藏存储。
8. 主页面背景使用淡米白 + 淡水彩纹理，不加入富士山和装饰文字。
9. 真实旅行内容使用写实照片。
10. More Features 使用浅色功能卡，不使用大幅写实照片抢主内容焦点。
11. 整体饱和度 / 对比度相对高饱和概念稿降低约 10%，但不得变成灰色后台。
12. 不使用传统 Admin Dashboard 模板替代设计。
13. 未冻结的 Token 使用语义变量，不直接把概念图颜色写死为全局品牌色。
14. 旅行灵感 / 目的地探索若需要真实业务页面，必须单独建立后续 WBS / Task。

## 18. 最终冻结结论

WBS 1.21 的正式结论：

> **TravelAssist 个人中心采用左侧五项一级导航 + 右侧旅行内容主页。视觉采用温暖、轻日式水彩质感的方案 D；日式元素集中在背景质感和 Sidebar 底部插画，真实目的地使用写实摄影。首页主信息流突出“下一次旅行”和“我的旅行”，旅行偏好与同行人仍保留一级导航但不在主页重复展示；My Trips 下方增加低视觉权重的“更多功能模块”，第一版包含旅行灵感、我的收藏、目的地探索，其中我的收藏复用现有 My Trips 收藏语义。整体色彩与对比度在保持旅行愉悦感的前提下，比高饱和概念稿降低约 10%。**

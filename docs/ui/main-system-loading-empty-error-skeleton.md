## 2. 冻结不变量

1. 子能力失败优先局部降级；Map/Route/AI 失败不等于行程删除。
2. 保留 Start/Planner 当前输入、选择、日期、筛选和有效内容；不通过 clear storage、重建 Trip、重载页面实现普通恢复。
3. 保护优先于保留：明确权限撤销或换账号后，不得继续展示原受保护内容、保存私有快照或泄露目标存在性。无敏感导航可保留。
4. Empty 是已确认零数据；失败/未加载/未知不是 Empty。首次使用和有效零结果不同。
5. Skeleton 只表达未知内容的几何，不表达百分比、阶段完成或业务结果。
6. 没有真实可测进度就不显示百分比、ETA、倒计时或完成勾选；不从 elapsed time 推算进度。
7. 重试最小失败操作；已确认零结果应改条件，不自动轮询。
8. 只有主资源不能安全呈现才阻断主内容；Header/安全返回保持，局部状态不得覆盖整页。
9. 同一 pending 动作立即阻止重复激活；其他安全区域可操作。视觉灰化不能代替语义和实际动作防重。
10. 只呈现安全用户语义，不拼接 raw SQL/Auth/Provider/stack/token；支持编号仅在已有安全编号机制下显示。
11. 图标、文字和语义共同传递状态；不靠红/绿或动画单独表达。
12. 状态 UI 不改变 Planner Map/Right/Bottom 的保护几何，不卸载已可用地图、不重排 Grid。
13. “已保存”“路线已更新”“预约已确认”“实时 AI”必须有相应真实拥有方结果。只结束 loading 不构成成功。
14. 关闭等待浮层不证明取消请求、业务回滚或保存成功；写入结果未知时先核对原操作，不换 key 绕过、不自动重交。
15. 未接入/不支持/缺配置不是网络暂时失败；没有现成有效恢复动作时不显示可点击的“重试”。
16. 本文不授权后端重试队列、离线同步、数据库/Provider 调用、AI apply、Booking/Payment 或任何新 operation/source。

## 3. 状态分类与选择

状态名是设计意图 ID，不是新 TypeScript enum 或 API schema。显示层只消费拥有方结果，不猜测 HTTP/SDK 私有细节。

| ID  | 语义                                   | 呈现与动作                                                    | 基础语义/公告                                              |
| --- | -------------------------------------- | ------------------------------------------------------------- | ---------------------------------------------------------- |
| L   | Initial page loading                   | 已知 shell 保留；必要主资源区域等候；只有依赖该资源的动作阻断 | 目标 `aria-busy=true`；单独一处短 loading 文本             |
| S   | Section loading                        | 仅一块 loading；有有效旧内容则保留并标记更新，无旧内容再用 K  | 该区域 busy；外部导航不 busy                               |
| K   | Skeleton（L/S 的视觉处理）             | 匹配真实容器、最多三行/每行三中性块；不画可操作假控件或假值   | 装饰组 `aria-hidden=true`；不聚焦、不逐块公告              |
| F   | Empty / first use                      | 读取成功且未创建/未选择；中性说明+一个已有建设性动作          | 常规标题/说明；初始 render 不强行 alert                    |
| N   | Empty / no result                      | 请求/筛选成功且零结果；保留条件，主动作调整条件               | 用户搜索完成可一次 polite 报零结果                         |
| E   | Recoverable error                      | 已知可恢复失败；原位 retry + safe secondary；保留用户状态     | 默认 polite；真正阻断用户动作且需要立即知道时一次 alert    |
| B   | Non-recoverable / permission / invalid | 无安全重试或缺前提；修正、返回、登录；隐藏不该展示的数据      | 标题与操作可读；权限错误不朗读敏感目标；按进入方式管理焦点 |
| D   | Partial degradation                    | 主流程可用，明确哪个区缺失；相关区局部说明                    | region 有可读名称；后台退化 polite，不打断全页             |
| C   | Generic connection loss                | 实际操作连接失败；未知原因用“无法连接”                        | 不因 `navigator.onLine` 单独判定服务或离线能力             |
| R   | Retry pending                          | 复用原失败区与按钮占位，单次操作正在重试                      | 原区域 busy，按钮状态可感知且不重复触发                    |

**选择顺序：**拥有方明确权限/非法结果 → 只遮除不安全部分并用 B；已知未开放能力 → B/D 说明；有可信内容+刷新 → S/D；无内容且请求未定 → L/S（结构已知可 K）；成功零结果 → F 或 N；确有失败 → E/B/C；子失败聚合为 D。不要用 Empty 隐藏未知，也不要因为出现两个局部失败自动升级全页阻断。

**并发显示：**每个 region 有一个当前主状态；D 可标记 L/S/E/B 的影响范围。页面不堆叠多个全宽报警。将局部失败放在对应区域；只有确有统一连接故障时展示一次通用提示，仍保留每区动作。旧请求晚到不得覆盖新条件/目标、重新弹开已关闭浮层或抢焦点。

**恢复转换：**E → 用户重试 → R → 已确认有效内容 / F / N / E / B。每次只宣布本次转换，错误未改变不重复播报。“重新载入”仅描述读取；写入、路线可用性、Booking/Payment 不套用通用成功文案。

## 5. 全局交互、几何与 motion 规则

### 5.1 Skeleton 与布局

- 有内容就保留可信内容；刷新不把整块旧内容抹成 Skeleton。
- 首次 Skeleton 使用最终标题行/缩略图槽/列表行的已知位置；未知高度采用当前容器给定空间，不推测数据量无限加卡片。
- 推荐区最多三行，每行最多三块（图槽、一到两条文字）；表单只占尚未加载的选项，不遮住已输入字段；Map 以既有示意/文字列表优先，不画假瓦片；Timeline 未知 duration 用普通条目占位，不画时间比例假行程。
- 状态 body 在既有 region 内滚动。原 Header、Tab、Day Selector、关闭和可用恢复入口不因错误文案增高移出可达区。字体放大/长翻译导致需要滚动时，允许 body 变高，但不改变保护 Grid 或裁掉文字。
- 无可用内容但结构也未知时使用简短 indeterminate loading；不用不匹配最终结构的 Skeleton。

### 5.2 Timing 与动作

触发后立即给局部按压/等待反馈；内容一旦实际就绪立即展示。没有人为最低等待、固定“看起来在思考”的延迟、自动超时数值或假进度。短动作可以不出现循环动画，状态文字始终可表达。具体 deadline/retry-after 由拥有方提供，不从设计稿猜出。

区域显隐沿用 `--motion-fast=140ms` / `--motion-normal=240ms`；若已有宿主需要 indeterminate spinner，可用 `--motion-slow=900ms` 的均匀循环，非阶段计时；Skeleton 默认静态，可选同一 slow token 的轻 opacity 脉冲，不做全幅扫光/闪烁。全页同时不超过一个显著循环指示器，各区文本仍独立。

重试期间原按钮位置不变、标签“正在重试…”。优先保留可感知焦点并以 `aria-disabled` 配合实际防重复处理；采用原生 disabled 的宿主需验证焦点不会意外落到 body。返回/关闭是否取消操作必须由已有能力决定；否则仅关闭展示，不承诺取消提交。离开带 dirty 内容时使用现成保护，不新增自动保存。

连接失败文案仅用于已确认未完成的读取/非写入操作；若提交结论未知，必须优先使用下面的 unknown outcome 呈现，不用“本次操作尚未完成”断言写入没有发生。

### 5.3 写入与未知结果

主系统目前的浏览器保存与 Engine 已验收事务不是同一个产品接线。本设计不能把 Engine reconcile 私有接口直接接入 Planner。若未来拥有方报告 unknown outcome，使用“暂时无法确认保存结果”，仅通过已有原操作核对能力恢复；没有核对能力就保持说明和安全返回，不虚构按钮。不得因为视觉 loading 消失而允许换 key、复制一份或自动重发。用户主动开始新操作的决策由业务拥有方另行定义。

## 6. Accessibility 规范

这些是实现验收要求，当前 TASK-066 未执行浏览器、读屏器或实际键盘测试。

- 所有恢复、关闭、返回、登录动作的可交互命中区域至少44×44px；不靠 hover 才显示，触控不能点穿到地图，邻近目标不可重叠。
- Tab/Shift+Tab 顺序跟随内容顺序；按钮支持 Enter/Space，Link 用 Enter。不得把 Skeleton/装饰 icon 加入 Tab。Tab/Day 控件继续使用原键盘模式，不重新定义箭头键。
- 只有被加载/更新的内容区 `aria-busy=true`，完成/错误/Empty 时清除。恢复按钮、取消和公告节点应置于不会被 busy 抑制的稳定区域；不把整个 body 标 busy。
- loading/局部失败/重试成功使用一个稳定的 `role="status"`（implicit polite）或等价 polite live region；不要重复嵌套 role=status + 另一公告；必要时 `aria-atomic=true` 读一次短摘要。Skeleton 动画无公告。
- 仅用户刚触发且无法继续、确需立刻感知的失败用一次 `role="alert"`；后台刷新失败、无结果、暂未接入都不 assertive。不要把整页/整张卡设置 alert。
- 页面导航初次失败可将焦点按原路由机制移到错误标题；局部异步变化不夺焦点。Retry 中留在触发点，成功后若按钮移除，移到原区域标题/第一个合理存活控件；不跳回页面顶部。
- 原模态 Dialog/Drawer 继续唯一焦点陷阱、背景 inert、可见标题和关闭；retry 不卸载重开 Dialog。Escape 先关闭当前最内层帮助/Popover，再按宿主关闭；关闭返回触发器，触发器已消失则回所属 region 标题。
- 原非模态 region/Popover 不设置全页 inert、不 trap focus。只读 InfoPopover 仍是 tooltip：说明通过 `aria-describedby` 可达，没有内部交互和额外 live region。
- 关闭不会销毁已有输入，除非原拥有方已有明确弃置行为且用户已知；认证失效时保护私有数据的规则优先。
- `prefers-reduced-motion: reduce` 下去掉轮转、脉冲、位移、扫光、自动滚动；保留静态形状和可见文字。不能只依赖全局0.01ms模拟“几乎静止”作为新状态动画验收，后续应实际确认静态显示。
- 字体放大、CJK/Latin fallback、focus clipping、hover/pressed/disabled 和真实背景合成都在后续3.7验收；本次没有测量数据。

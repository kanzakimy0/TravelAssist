# TravelAssist 行程详细页面设计规格

> 状态：v1.1 / 核心信息架构、AI 双阶段判断与状态语义冻结  
> 更新日期：2026-09-05  
> 适用范围：Web 行程详细 / 执行页面；未来手机 App 共用同一业务模型  
> 参考：现有行程主页面、我的旅行 / 外部订单设计、欧洲自驾高密度执行型行程样本

---

## 1. 页面重新定位

“行程详细页面”不再承担“规划旅行”的职责。

三个页面必须严格分工：

| 页面 | 用户问题 | 核心 |
|---|---|---|
| 行程主页面 / Planner | 我要怎么安排？ | 地图、方案、偏好、重新规划 |
| 行程详细页面 / Trip Detail | 我今天具体怎么走？ | 日期线、执行时间轴、当前状态 |
| PRO 实时旅行助手 | 现实和计划不一致怎么办？ | 风险监控、提醒、后续调整 |

行程详细页的核心定义：

> **一条可以真正照着执行的旅行时间轴。**

页面不是“景点列表”，也不是“旅游文章”，而是完整包含：

- 景点 / 活动
- 驾驶
- 公共交通
- 徒步
- 停车
- 取车 / 还车
- 入住 / 退房
- 用餐
- 预约 / 取票 / 排队
- 缓冲时间
- 天气备选
- 硬时间约束
- 实际延误与后续影响

> **上方横向旅行日期线 + 下方当天纵向执行时间轴 + 右侧辅助执行栏**

地图从规划页的“视觉主体”降级为详细页的“辅助工具”。

### 2.1 桌面端比例

- 顶部全局导航：紧凑，不抢占页面。
- 日期线：横跨整个内容区，固定在顶部导航下方。
- 主内容：
  - 当天执行时间轴：约 70%–75%。
  - 右侧执行辅助栏：约 25%–30%。
- 页面滚动时：
  - 顶部导航可保持。
  - 日期线必须 Sticky。
  - 右侧执行栏可 Sticky。
  - 时间轴独立正常纵向滚动。

## 3. 顶部旅行日期线

日期线是整个页面的第一核心导航。

它回答：

> **我现在处于整趟旅行的哪一天？**

### 3.1 每个日期节点显示

默认显示四层信息：

```text
3/19
第3天
CK → 维也纳
●
```

内容包括：

1. 月 / 日
2. 第几天
3. 当天主要地点或跨城方向
4. 状态

状态：

- `✓` 已完成
- `●` 当前 / 今天
- `○` 未来
- `!` 当天存在需要处理的异常
- `锁` 存在重要硬约束时，仅在必要时辅助提示

### 3.2 长行程

7 天以内可以完整展示。

超过可视宽度：

- 横向滚动。
- 当前日期进入页面时自动居中。
- 左右保留箭头。
- 提供“今天”快速返回按钮。
- 不缩小字体强行把 20 天全部塞进一屏。

### 3.3 点击日期

点击日期后：

- 下方时间轴切换到对应 Day。
- 右侧地图切换当天路线。
- 预约、天气、状态一起切换。
- 页面不跳转到新的页面层级。
- URL 应保存当前 Day，支持刷新和分享后回到同一天。

### 3.4 日期线不承担的功能

详细页不再显示：

- `1日 / 3日 / 全日`
- 方案 1 / 2 / 3
- 旅行偏好设置
- “重新生成路线”

这些属于 Planner。

---

## 4. 日期线下方：当天摘要条

日期线下面保持一个轻量摘要，不做大卡片。

示例：

```text
第3天 · CK → 维也纳
3月19日 周四

08:00–20:30
🚗 驾驶 3h40m
🚶 步行 5.8km
📍 8个执行节点
🔒 1个硬预约
⚠ 2个可删项目
```

当天摘要只展示对“执行”有帮助的数据。

不展示长篇目的地介绍。

## 5. 当天时间轴：页面主体

时间轴按：

> **地点 / 行动 → 移动 → 地点 / 行动 → 移动**

连续呈现。

不使用“每个元素都是巨大卡片”的设计。

### 5.1 基础结构

```text
08:00  ● 酒店退房
         Hotel A

         │
         │ 🚗 驾驶
         │ 1h35m · 112km
         │ 高速费 €8
         │
09:45  ● P+R 停车
         预计停车 10min

         │
         │ 🚋 T1
         │ 22min
         │
10:20  ● 美术馆
         10:20–12:00
         核心
         ✓ 已预约

         │
         │ 🚶 12min
         │
12:20  ○ 午餐
```

### 5.2 后台时间粒度与前台显示

系统内部允许：

- 1 分钟时间戳
- 5 / 10 / 15 分钟计算粒度

但前台不直接显示 15 分钟 Excel 网格。

连续项目合并显示：

```text
10:15–12:15
Untersberg 缆车往返
预计 2h
```

原则：

> **后台精确，前台连续。**

## 6. 行程节点类型

必须支持至少以下正式节点。

| 类型 | 示例 |
|---|---|
| 景点 | 博物馆、城堡、神社 |
| 活动 | 演出、导览、体验 |
| 酒店 | 入住、退房、返回酒店 |
| 餐饮 | 早餐、午餐、晚餐、咖啡 |
| 自驾 | A → B 驾驶 |
| 公交交通 | 火车、地铁、电车、巴士、船 |
| 徒步 | 两点之间步行 |
| 停车 | P+R、停车场、路边停车 |
| 租车 | 取车、验车、加油、还车 |
| 票务操作 | 取票、换票、安检、排队 |
| 缓冲 | 预留、休息、机动时间 |
| 任务 | 行李寄存、购物、换汇、办理手续 |
| 条件节点 | 天气允许时、仅晴天、备用路线 |

## 7. 节点三层信息结构

继续使用整个 TravelAssist 已确定的：

> **默认简洁 → 点击展开 → 完整详细**

### 7.1 第一层：默认显示

用户快速扫时间轴时只看到：

```text
10:20–12:00
美术馆

核心 · ✓ 已预约
预计停留 1h40m
```

### 7.2 第二层：时间轴内展开

点击后原位展开：

```text
10:20–12:00
美术馆

核心 · ✓ 已预约
门票 €18
预约 10:30
建议 10:15 到达
入口：东门
洗手间 / 寄存可用

[显示票券]
[导航]
[查看完整详情]
```

### 7.3 第三层：完整详情

PC：

- 在右侧栏打开详细内容。
- 不把用户强制带离当天时间轴。

手机：

- 使用可上拉 Bottom Sheet。

可包含：

- 基本介绍
- 营业时间
- 门票
- 预约
- 最晚入场
- 推荐游览顺序
- 拍照点
- 设施
- 无障碍
- 洗手间
- 行李寄存
- 注意事项
- 联系方式
- 周边餐饮 / 便利设施

## 8. 移动段是正式的一等数据

交通不能只是一个小图标。

### 8.1 简单移动

默认：

```text
│ 🚶 徒步 12min · 850m
```

### 8.2 复杂公共交通

展开：

```text
🚶 酒店 → 车站
8min / 550m

🚃 S1
中央站 → 老城站
18min

🚶 老城站 → 景点
7min / 420m

总计 33min
预计到达 10:17
```

### 8.3 自驾

自驾段至少支持：

```text
🚗 Salzburg → Hallstatt
1h18m · 78km

高速 / 收费
预计油费
停车目标
预计停车时间
P+R / 接驳
加油 / 充电建议
冬季装备 / 限行提示（需要时）
```

停车必须能够作为独立节点进入时间轴。

## 9. 优先级与硬约束

从高密度欧洲自驾行程可以明确：

> 用户不是简单按顺序旅行，而是在“不能动的项目”和“可以牺牲的项目”之间执行。

行程节点至少需要以下语义：

### 9.1 硬约束

例如：

- 航班
- 火车
- 已预约导览
- 演出
- 餐厅预约
- 还车时间
- 最晚入场
- Check-in 截止

视觉：

```text
🔒 15:00 盐矿预约
建议最晚 14:40 到达
```

### 9.2 行程优先级

建议后台支持：

1. 必须保留
2. 核心
3. 次核心
4. 可删
5. 备用

前台正常状态不要到处显示五种标签。

只有用户展开、进入调整模式或发生延误时才强调：

```text
核心
可删
备用
```

## 10. 实际状态与计划状态

详细页必须同时理解：

> **计划时间** 与 **现实时间**

节点状态：

- 未开始
- 即将开始
- 进行中
- 已完成
- 跳过
- 延误
- 取消
- 被替代

示例：

```text
原计划 11:20

清水寺
预计抵达 11:37
+17min
```

完成项目弱化：

```text
✓ 09:00 伏见稻荷
```

当前项目最突出：

```text
● 当前
前往清水寺
剩余 12min
```

未来项目保持正常或轻度弱化。

## 11. 右侧“今日执行”辅助栏

右栏不再是 Planner 的设置栏。

它只回答四个问题：

1. 我在哪里？
2. 下一步是什么？
3. 今天有没有问题？
4. 有什么必须马上操作？

### 11.1 小地图

右栏顶部保留辅助地图。

显示：

- 当前定位
- 当前移动段
- 下一站
- 当天路线
- 选中节点

提供：

```text
[展开地图]
```

点击可进入大地图 / 全屏地图。

地图不是详细页默认主体。

### 11.2 下一步卡片

这是右栏最重要的卡片。

示例：

```text
下一步

11:20 清水寺
还有 18min
预计抵达 11:19

[开始导航]
[查看详情]
```

如果下一步是操作：

```text
下一步

13:00 餐厅预约
建议 12:50 到达

3人
已确认

[显示预约]
```

### 11.3 需要注意

只显示当前真正影响旅行的事项：

```text
需要注意

⚠ 当前延误 +17min
⚠ 16:00 后降雨概率 80%
⚠ 还车必须在 19:00 前完成
```

不把普通资讯伪装成警告。

### 11.4 预约 / 票务

只展示今天：

```text
预约 / 票务

✓ 10:30 博物馆
✓ 13:00 午餐
✓ 17:30 音乐会
```

点击直接定位时间轴对应项目。

## 12. 订单必须嵌入时间轴

内部订单和外部订单在用户看来没有区别。

例如：

```text
15:00
环球影城

🎫 门票
✓ 已确认
3人

[显示二维码]
```

酒店：

```text
19:30
酒店入住

✓ Booking.com 已确认
2间房
入住 15:00 后

[查看订单]
[联系酒店]
[导航]
```

Partner 来源只是属性。

不要让用户为了找到票券离开当天执行页、再进入多个订单层级。

## 13. 天气与条件行程

天气不是页面顶部一个天气图标就结束。

必须支持：

- 晴天线路
- 雨天线路
- 大风 / 缆车停运
- 高温
- 降雪
- 日落 / 光线条件
- 其他影响当前活动的条件

正常情况下不占大量空间。

出现触发条件时：

```text
⚠ 16:00 后预计大雨

当前：
16:00 户外花园
17:30 老城步行

建议：
16:00 室内博物馆
18:00 提前晚餐

[查看调整]
```

## 14. “重新生成”改为“调整后续行程”

详细页禁止使用：

```text
重新生成路线
```

统一改成：

```text
调整后续行程
```

逻辑：

- 当前时间之前：冻结。
- 已完成项目：冻结。
- 硬约束：默认锁定。
- 用户手动锁定项目：冻结。
- 只重算后续可调整部分。

示例：

```text
14:20 当前

保持不变
✓ 上午全部行程
✓ 15:00 硬预约

允许调整
○ 16:30 景点 A
○ 18:00 景点 B
○ 19:30 晚餐
```

---

## 15. AI 调整必须先预览，再应用

AI 不得未经用户确认直接重写行程。

必须提供 Diff：

```text
因为当前延误 +35min

原计划
16:00 湖边 75min
17:45 小镇 60min
19:30 晚餐

建议
16:15 湖边 45min
17:30 小镇 30min
18:45 前往晚餐

保持：
✓ 19:30 餐厅预约

[保持原计划]
[采用调整]
```

用户采用后：

- 更新时间轴。
- 更新地图。
- 更新预约风险。
- PRO 同行人同步到相同版本。

---

## 16. 延误恢复逻辑

发生延误时，系统应优先：

1. 保留硬约束。
2. 保留“必须保留”项目。
3. 压缩缓冲。
4. 压缩允许缩短的停留时间。
5. 删除“可删”项目。
6. 启用备用项目。
7. 最后才建议更改重要预约。

用户看到的是结果，不需要暴露复杂算法。

示例：

```text
当前延误 +25min

不受影响
✓ 15:00 盐矿预约
✓ 19:30 酒店入住

建议恢复
Gosausee 75 → 45min
Ramsau 60 → 30min

预计 17:20 恢复原时间表
```

## 17. 免费会员与 PRO

原则：

> **免费用户能够完整执行旅行；PRO 提供自动化、实时判断与多人协同。**

| 功能 | 免费 | PRO |
|---|:---:|:---:|
| 查看完整日期线 | ✓ | ✓ |
| 查看完整时间轴 | ✓ | ✓ |
| 地图 | ✓ | ✓ |
| 当前定位 | ✓ | ✓ |
| 查看订单 / 票券 | ✓ | ✓ |
| 手动调整行程 | ✓ | ✓ |
| 基础 AI | 每日次数限制 | 更高额度 |
| 天气风险主动判断 | — | ✓ |
| 交通异常主动判断 | — | ✓ |
| 实际进度偏差判断 | — | ✓ |
| 自动提醒 | — | ✓ |
| AI 调整后续行程 | — | ✓ |
| 同行实时同步 | — | ✓ |
| 离线完整行程 | — | ✓ |
| 导入 / 导出完整行程 | — | ✓ |
| AI 联系酒店 / 餐厅并翻译 | — | ✓ |

预订酒店、门票、餐饮、交通等 Affiliate / Partner 功能不因会员状态限制。

## 18. 同行人

PRO 可以在右栏轻量显示：

```text
同行

李先生   ● 已同步
王小姐   ● 已同步
```

只有发生异常时再强调：

```text
王小姐
距离当前路线约 580m
最后同步 2min 前
```

默认不做大型“人员追踪页面”。

同行定位属于辅助安全 / 协同行为，不抢占行程主体。

## 21. 详细页明确不包含

为了防止与 Planner 功能重叠，以下功能不得进入详细页主界面：

- 推荐方案 1 / 2 / 3
- 全套偏好设置
- “更多行程设置”
- 1日 / 3日 / 全日地图规划切换
- 大型方案比较
- 重新生成整个旅行
- 大量“为您推荐的其他景点”
- 首页式目的地内容流

详细页可以允许：

- 手动微调单个项目
- 调整后续行程
- 查看附近备选
- 插入一个新项目

但这些操作不能破坏“执行时间轴”的页面定位。

## 24. 最终冻结原则

行程详细页面最终遵循六条原则：

1. **上面是整趟旅行日期线，下面是当天行程。**
2. **当天行程以纵向执行时间轴为页面主体。**
3. **地图是辅助，不再与 Planner 一样占据主体。**
4. **交通、停车、入住、用餐、票务都是正式行程节点，不是附属文字。**
5. **正常状态保持简洁，复杂信息逐层展开。**
6. **AI 只调整当前时间之后的可调整行程，并且必须先预览、后应用。**

最终产品语义：

> **Planner 负责把旅行计划出来；Trip Detail 负责让用户真的走完这趟旅行；PRO Assistant 负责现实发生变化后，让后面的旅行继续成立。**

## 25. AI 判断双阶段模式

行程详细页的 AI 判断不使用一套逻辑贯穿整个生命周期。

### 25.1 行程前：Planning Review

时间范围：

```text
行程建立后 → 出发前 T-48h
```

核心问题：

> **这份行程是否合理、完整，并且符合用户需求？**

主要判断：

- 需求匹配
- 时间与密度合理性
- 路线与交通合理性
- 营业日 / 季节条件
- 同行人适配
- 住宿与餐饮安排
- 预约完整性
- 硬约束冲突
- 是否缺少必要预约
- 是否准备备用方案

此时右栏使用：

```text
AI 行程检查
```

### 25.2 行程中：Execution Monitor

从整趟旅行第一段正式行程开始前 `T-48h` 自动进入执行监控模式，一直持续到行程结束。

核心问题：

> **按照现在的现实情况，这份行程还能不能顺利执行？**

综合判断：

- 最新天气 / 小时级天气
- 航班、铁路、公共交通
- 道路封闭、事故、拥堵
- 临时闭馆 / 设施停运
- 当前定位
- 实际出发 / 抵达时间
- 当前延误
- 实际停留时间
- 当前和后续预约
- 硬约束
- 停车 / 接驳
- 用户临时修改
- 后续连锁影响

此时右栏切换为：

```text
AI 实时行程
```

或：

```text
今日行程状态
```

详细判断规范见：

`docs/ai/trip-judgement-two-phase.md`

## 26. AI 状态与预约状态分离

时间轴上的状态分为两个独立维度。

### 26.1 AI 判断

```text
⚠ 黄色感叹号 = 需要用户确认 / 存在风险
❗ 红色感叹号 = 已确认或高置信度存在执行问题
```

黄色与红色必须同时通过图标、颜色和文字表达，不依赖颜色作为唯一识别方式。

### 26.2 预约状态

```text
✅ = 预约 / 订单已确认
❓ = 预约状态未知 / 待确认
```

两种状态可以同时存在：

```text
15:00 美术馆

✅ 门票已确认
❗ 当前预计无法按预约时间抵达
```

### 26.3 左右联动

时间轴只负责快速标记状态；右侧负责解释：

- 发生了什么
- 为什么这样判断
- 影响哪些后续行程
- 数据 / 信息更新时间
- 建议怎么处理

点击时间轴中的 `⚠ / ❗ / ✅ / ❓`：

- 右栏定位到对应详细说明。

点击右栏某条说明：

- 左侧时间轴自动定位对应行程节点。

### 26.4 阶段差异

同一状态在两个阶段的判断依据不同。

行程前黄色：

```text
⚠ 行程过密
⚠ 建议确认是否需要预约
⚠ 户外项目建议准备雨天备用
```

行程前红色：

```text
❗ 固定休馆日冲突
❗ 已确认预约互相重叠
❗ 交通时间无法衔接
```

T-48h 后黄色：

```text
⚠ 降雨可能影响户外活动
⚠ 当前换乘仅剩 7 分钟
⚠ 延误开始影响后续预约
```

T-48h 后红色：

```text
❗ 火车已取消
❗ 景点临时闭馆
❗ 当前预计无法赶上硬预约
❗ 原道路已封闭
```

最终原则：

> **行程前 AI 是“审计划”；T-48h 后 AI 是“盯执行”。**

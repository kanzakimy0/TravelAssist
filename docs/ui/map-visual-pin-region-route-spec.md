## 3. 底图与地图局部色彩

### 3.1 底图方向

使用真实地图底图；降低无关商业 POI 和次级路网的视觉权重，保留道路、站点、地名的可读性。陆地偏暖米灰，水域偏灰蓝，绿地偏低饱和灰绿。自然绿地不等于绿色品牌主色。

不对整个地图 Canvas 叠加统一低透明度或 CSS 滤镜来“降饱和”：那会连路线、图标和文字一起变淡。应在后续实现中使用当前地图样式允许的配置；本项不强制更换 Mapbox style、不假设特定底图图层 ID 存在。

默认维持现有平面规划视角，不新增 3D 建筑、地形倾斜或持续旋转。樱花装饰不得覆盖路线、道路、地名、署名或命中区域。

## 4. 视觉角色与业务类型分离

| 对象 | 默认表达 | 选中后 | 不应表达 |
| --- | --- | --- | --- |
| 正式景点/活动 | 圆形象征图或类别图标，独立顺序号 | 名称、日期、类型、执行状态 | 用照片推断已加入或已预约 |
| 候选/备选地点 | 较轻的图标 Pin，无行程序号 | 推荐理由与明确加入动作 | 看起来已经成为正式行程 |
| 正式酒店 | 床图标/象征图，住宿节点语义 | 入住/退房及实际确认状态 | 仅“已选择”就显示已预订 |
| 正式餐厅 | 餐具图标/象征图，餐饮节点语义 | 对应餐次、时间、实际预约状态 | 把推荐美食区域当作餐厅地址 |
| 交通节点 | 站点/机场/港口对应图标 | 路段与换乘说明 | 以单一公交图标代替全部交通 |
| 推荐住宿/餐饮区 | 轻填色与区域标签 | 区域说明，再显示具体候选 | 随意给出精确库存或步行可达承诺 |
| 当前定位 | 独立定位符号与精度信息 | 定位时间、状态、重新定位动作 | 未取得位置却显示示例定位点 |

这些是展示角色，不新增 POI 主分类。分类和标签引用 1.10；正式业务字段由对应 Schema / Contract WBS 决定。

## 5. Pin 尺寸、图片与命中区

尺寸均为 CSS px；它们不是素材库“大/中/小图片”三个生产尺寸。

| 状态/用途 | 可见外形 | 图标参考 | 命中要求 |
| --- | --- | --- | --- |
| 候选紧凑 Pin | 直径 20 | 12–14 | 优先 44×44 的透明矩形命中框；冲突时进入聚合/列表 |
| 正式行程 Pin | 直径 32 | 16–18 | 44×44 |
| 当前选中 Pin | 直径 40，外侧 2px 深描边 | 20 | 不小于 44×44 |
| 顺序号附标 | 直径 16，最多两位；更多位改短文字 | 11–12 文字 | 非独立按钮，随主 Pin 命中 |
| 聚合 Pin | 直径 36–44 | 清晰数字 | 不小于 44×44 |

命中框不能简单叠满地图互相抢点击；地理密集处优先保留坐标真实，再用明确的多对象入口。44×44 是本项目触控目标，不把它错误称为 WCAG AA 通用最低值。WCAG 2.5.8 有 24×24 与例外规则，地图密集点仍应提供等价入口。[W3][W4]

象征图来自已审核素材或获得许可的数据源，缺图用类别图标，不用错城市、错景点的通用照片冒充。正式 Pin 可用方形 64/96px 级资源满足显示密度，但必须经现有 Asset Registry 解析；这只是消费尺寸建议，不生成素材、不改生产单。图片失败不能改变 Pin 大小、坐标、顺序号或可访问名称。

## 6. Pin 状态与组合优先级

普通态轻边框；悬停态仅提高边界和短名称，不播放循环跳动；选中态以深描边、名称和明确“已选中”语义表达；键盘焦点使用独立可见轮廓，不能只靠阴影。

信息维度相互独立：

- 顺序号：这一天第几站。
- 类型图标：地点或活动是什么。
- 预约标识：订单实际确认结果。
- 风险标识：当前执行问题。
- 选中轮廓：用户正在查看什么。

风险与预约同时存在时，Pin 的紧凑状态位优先显示最高风险，快速卡保留两者，例如“门票已确认；预计到达晚于预约时间”。未知/未接入不显示绿色正常。`fixedTime` 使用锁定语义，不等于完成或安全。

默认 Pin 不放普通标签 Chip；选中 Pin 最多 1 个类型、1 个执行提示。快速卡最多 4 个普通标签，不重复结构行里已有的预约/营业信息。关键风险进入专门状态区，不因普通标签配额被截掉；这兼容尚待验收的 1.10 输入。

## 7. 重叠、聚合与密度

### 7.1 正式节点和候选分开

候选可以按地理邻近聚合，数字表示当前过滤后去重的实体数量。聚合数字不是评分、热度、预约数量，也不是未经确认的实时搜索总数。

正式行程节点不混入普通候选聚合。正式节点重合时显示“此处 N 个行程”入口，打开按日期/时间排序的节点列表；同一酒店多晚住宿、同一地点重复访问仍保留不同 `tripItemId`。不能按 `poiId` 去掉正式行程次数。

选中对象保持独立可见；聚合扩大后优先适配成员范围。达到最大缩放、成员完全同坐标或继续放大无收益时，直接打开列表，禁止无限放大。展开视觉若使用引导线，仅调整标签显示位置，不篡改地理坐标。

### 7.2 避让优先级

焦点/选中对象 > 当前范围风险与固定节点 > 正式起终点/住宿/行程节点 > 当前搜索结果 > 普通候选。

优先隐藏候选名称、降低候选密度，再将重叠正式节点改为可访问的多对象入口。不能为了保持画面干净，让用户失去正式节点的访问途径。缩放中的排序应稳定，平移结束后更新密度，避免 Pin 跳动洗牌。

### 7.3 参考密度

单日默认候选约 3–5 个；三日默认每日至多突出 3–4 个核心地点，其余正式节点通过缩放/节点列表访问；全程只突出城市、阶段锚点、跨城交通和必要住宿锚点。这些是展示预算，不是推荐算法的结果数量限制。

## 8. 缩放层级

以下为验收候选，后续实现按当前底图实际视觉校准；日期过滤先于缩放规则。

| Map zoom | 地图默认粒度 | 名称与图片 |
| --- | --- | --- |
| 小于 8 | 城市/阶段与跨城关系 | 不铺景点照片 |
| 8 至小于 12 | 当前范围主要锚点，候选聚合 | 仅重点短名称 |
| 12 至小于 15 | 正式节点、主要交通、推荐区 | 保持可读密度，候选次要 |
| 15 及以上 | 街区细节与入口位置（有数据时） | 允许更多名称，不无限增加照片 |

选中对象在不同缩放下不得无提示消失。远距全程模式不能仅因 zoom 较高就自动展示全旅程所有普通 POI。推荐区显示由模式与过滤共同控制，不只依赖 zoom。

## 9. 推荐区域

住宿区与餐饮区使用低透明度填色、细轮廓、类型图标和名称；默认无大面积高饱和热力色。午餐/晚餐通过餐次标签区分；同一区域承担两餐时合并底图几何、列出两项时间语义，不能重复叠色成“更热门”。

区域默认轮廓 1px，主动查看时 2px 深色轮廓；重要可读标签放在稳定浅色底上。区域相交时提供“此处 2 个推荐区域”选择，不用混合颜色创造第三种业务含义。

只展示真实提供的 polygon/边界。只有中心点时用“推荐位置/周边”标记，不画任意圆圈冒充行政边界、5 分钟步行圈或推荐覆盖范围。真实等时圈、营业、价格和库存留给 Provider 与业务任务。

点击区域先解释“为什么住/吃这里”，再列具体酒店/餐厅。用户确认具体酒店作为行程节点后，隐藏对应晚的默认住宿推荐区；不隐藏其他晚仍未确定的区域。需要更换时可明确重新打开备选。选择酒店不会自动把订单状态改为已预订；订单取消也不能静默删除住宿计划或自动选新酒店。

## 10. 日期范围与模式

“当前日”在本文件指用户选中的行程日，不是设备所在时区的今天。

| 模式 | 彩色主体 | 灰色上下文 | 控件与排除内容 |
| --- | --- | --- | --- |
| Planner 单日 Dn | Dn 正式路线/节点 | 仅 Dn−1 与 Dn+1 路线 | 地图右上第 N 天；非当日普通 Pin/区域隐藏 |
| Planner 三日 Dn–Dn+2 | 所选三日路线；日标签写实际日号 | 仅 Dn−1 与 Dn+3 路线 | 起始日选择保持原位；不显示其他天普通节点 |
| Planner 全日 | 城市/阶段、跨城主线 | 不额外铺整趟细碎灰线路网 | 不显示三日起始日下拉 |
| Detail Dn | Dn 正式执行路线/节点 | 仅 Dn−1 与 Dn+1 路线 | 日期放底栏顶部；地图无 1日/3日/全日 |

日期索引在有效旅程范围内裁剪。三日仅允许完整连续三日窗口；不足三天时禁用三日并解释原因，仍保留单日/全日。不补造第三天、不重复同一天。

Planner → Detail 继承方案、行程、选中日和地图实例；返回 Planner 恢复其原规划范围，不因查看 Detail 改写计划。过滤后不可见的旧选中对象应关闭旧卡片并说明范围变化，不能留下悬空卡片或无提示跳回其他日期。

## 11. 路线的颜色与线型

### 11.1 颜色只管日期/选中层级

优先保留现有方案已分配的日期色；不能在每次切换三日窗口时重新按“左/中/右”分配颜色。实际日号始终显示，颜色不是唯一索引。

对尚无日期色的新方案，本轮提供三色候选：`#1578E8`、`#8057A6`、`#217D83`，按旅程绝对日序稳定分配；循环复用时必须配 Dn 标签，不发明十几种颜色。是否采用该候选需用户验收，已有配色不强制替换。

Detail 当前日保留方案原有日期色，前后日中性灰。成功/注意/风险只影响独立标识，不能把整条路线改成绿色/黄色/红色来代替日序。

| 路线状态 | 参考线宽 | 辅助表达 |

| 选中路段 | 6px | 深轮廓或清晰描边，标注方式/时间 |
| 相邻日期上下文 | 2px | 浅灰；无需照片 Pin 和全部方向箭头 |
| 当前范围候选替代路线 | 3px | 点划线及“备选”文字，不伪装已采用 |
| 未取得真实几何的空间连接 | 2px | 明确“示意连接，非真实路线”，不能替代导航 |

线宽以逻辑视觉目标验收，后续实现按地图像素密度与缩放插值。重叠跨日路线默认显示当前范围主体，通过标签/列表访问其他日期；不得平移真实道路坐标制造“分开了的两条街”。

### 11.3 交通方式不用更多强色

步行使用圆点虚线与步行图标；道路交通使用实线并写明自驾/公交/出租车；轨道交通使用实线加轨道图标和线路名称；船舶使用点划与船图标。航空/跨海连接只在有可信几何或明确示意标识时展示。

线型是辅助而不是唯一判断：虚线也可能表示候选或示意，因此“步行/备选/示意”文字必须能在对应说明中看到。交通标签显示真实已有的方式、时长、距离及数据时间；未知显示“待获取”，不从直线长度伪造真实路程或耗时。

起点/终点使用清楚的起/终标识；中间序号对应时间轴。往返同一路段保留两个不同时间/方向记录，通过选中态或卡片切换，不把它们错误去重为一次移动。跨午夜以行程时区、实际时间/节点归属表达，不凭浏览器本地日期自行切段。

## 12. 图层顺序与点击优先级

### 12.1 地图内部逻辑层级（从下到上）

底图地表/道路 → 推荐区域轻填色 → 相邻日期路线 → 当前范围路线/casing → 选中路线 → 正式节点与候选 → 选中节点/定位 → 必要业务标签。

底图关键地名、站名应可读；区域和路线不得把它们永久盖掉。Mapbox 的样式层不是 DOM `z-index`：普通样式按实际图层与插入位置处理；Mapbox Standard 使用它提供的 slot。地形/globe 渲染可能调整 fill/line 与 symbol 顺序，不能把本表当作任意样式都能直接复制的图层 ID 列表。[M1]

### 12.2 DOM 工具层

继承 v0.5 现有层级关系：地图 < 控件/渐变 < 底栏/右栏 < Logo/搜索/用户操作 < 地图快速卡 < 高级设置 < 确认对话框。后续实现先核对现有 stacking context，不全局提升所有浮层。

渐变和纯装饰层 `pointer-events: none`；交互卡片自身可接收事件，但不能给整片透明遮罩吞掉地图拖拽。Modal 的遮罩例外，按其既有模态语义阻止背景操作。

### 12.3 命中顺序

可交互控件/当前卡片 > 选中/正式 Pin > 候选 Pin > 路段 > 区域 > 地图空白。相同位置多个可交互对象必须有选择列表，不按最后绘制顺序随机决定。范围外隐藏对象不继续响应点击或键盘焦点。

## 13. 地图安全区域与响应式

相机适配与卡片位置基于实际可见地图矩形，减去右栏、底栏、顶部动作、左侧图层栏、打开的 Sheet、署名区和安全边距。不能拿整个浏览器窗口直接 `fit bounds`，导致目的地落在面板背后。

安全边距以 12px 为候选；后续实现测量真实遮挡矩形，不写死一套适用于所有视口的偏移。仅在打开卡片或选择明确对象需要时小幅平移；拖动地图后不持续把用户拉回中心。不因 hover 触发昂贵重算或全图飞行动画。

桌面快速卡宽度参考 300–320px，并限制在可见安全区；狭窄视口放不下时进入既有 Drawer/Sheet 模式，不强行缩小文字。地图始终保留，不改 document 级滚动原则；在文本放大/辅助技术场景必须提供可滚动内容与等价列表，不能为了固定首屏而裁切信息。

本项沿用实际已验收的响应式机制。1180px 等尺寸是否使用 Drawer 的既有差异不在本轮重新判定为通过或失败；后续实现需在独立任务中回归，不能用本规范推翻先前范围记录。

## 14. 选中、快速卡与跨视图联动

点击正式 Pin/时间轴节点：使用现有 `tripItemId` 选择同一对象，地图高亮，时间轴滚动到对应节点；右栏只在现有槽位展示相关说明。点击交通段使用 `segmentId` 或对应既有路段身份。尚未加入行程的候选按其候选 ID 选择，不伪造 `tripItemId`。

快速卡顺序为：名称 → 日期/时间和类型 → 必要状态 → 少量理由 → 明确动作。加入行程、查看详情、预约入口分别表达；“选择/查看”不能执行“加入/付款”。

再次选择其他对象替换当前卡片；空白点击或 Escape 只关闭最高层可关闭浮层。不能一次 Escape 清空所有面板或丢失编辑内容。焦点返回触发对象；触发 Pin 因范围变化不可见时，返回对应日期控件或等价列表项。

地图卡片动作不把业务数据写在 Mapbox feature 中。固定预约、已确认酒店及手动选择保护仍由现有 Trip State/Contract 控制。地图相机状态只属于视图状态，不因平移缩放触发行程保存或 AI 重新规划。

## 15. 无障碍与动效

关键文字目标至少 4.5:1，必要图形/交互状态目标至少 3:1；不用透明度、红绿颜色或照片作为唯一说明。灰色上下文不承担唯一任务信息，日期关系同时存在于文字列表。[W1][W2]

Canvas Pin 必须通过有序行程列表/节点列表获得等价键盘入口；不要求把所有背景商业 POI 加入 Tab 顺序。方向与缩放操作有按钮替代拖拽，多对象列表可用键盘选择，选中状态可由辅助技术读到。

可访问名称包含实际日期/序号、名称、角色与必要状态，例如“第 2 天，第 3 站，示例景点，已加入行程，需确认预约”。完整名称在详情可见；地图短名允许截断，但不能只剩无法辨认的省略号。

过渡参考 160–220ms；模式切换继承已有 180–260ms 范围。减少动态效果模式关闭非必要缩放飞行、Pin Morph 和脉冲，不强制平滑动画。无持续闪烁和自动弹出循环。

帮助问号外观不大于相邻文字的 80%，但可点击/聚焦命中框仍按触控目标设计；桌面 hover、键盘 focus、触控点击都必须能获取同一说明，不把“悬停显示”错误实现成触屏无入口。

## 16. 数据未知、网络失败与定位

| 状态 | 地图表现 | 仍可操作 | 禁止 |
| --- | --- | --- | --- |
| 首次加载 | 克制的地图加载提示，布局稳定 | 既有返回/设置入口 | 假装真实路线已返回 |
| 范围或方案加载 | 可保留上一有效地图并标明正在更新 | 取消/返回原范围 | 把旧路线误标成新方案 |
| Token 缺失/地图失败 | 继承现有 fallback，说明地图暂不可用或示意模式 | 行程/节点列表与返回 | 宣称 fallback 等同真实导航 |
| 路线数据失败 | 保留已知节点；真实旧路线需标时效 | 节点详情、重试 | 自动连线后隐藏“示意” |
| 无搜索结果 | 清楚显示当前范围无结果 | 修改条件/取消搜索 | 静默扩大搜索并冒充原结果 |
| 图片失败 | 类别图标替代，尺寸稳定 | 原 Pin 的全部功能 | 用不相关照片替代真实景点 |
| 定位拒绝/不可用 | 明确未定位，不画当前位置 | 手动浏览/重新授权入口 | 用默认城市当用户位置 |
| 数据陈旧/状态未知 | 显示来源时间或待确认 | 查看已有计划 | 无依据显示实时/已确认/安全 |

当前位置仅在已有授权与真实定位结果下显示；精度圈来自实际精度值，位置更新时不默认持续追踪。主动定位才适配视野，手动拖图退出跟随。本项不新增采集、上传或保存位置数据的功能。

重试策略、计费 API 与缓存有效期留给 7.10/7.11；此处只规定用户能看到什么，不把通用超时秒数冒充所有 Provider 的规则。

## 17. 来源署名、素材与截图边界

使用 Mapbox 的样式/数据时保留其适用的 Logo 和来源署名；不得被贴边底栏、渐变、Sheet 或截图裁切掉。允许按适用 API 移到地图可见角落，但不能擅自改造 Logo 或使署名不可读。不同数据源的额外署名按实际来源处理，不简单删到只剩 TravelAssist Logo。[M2]

后续验收需同时检查桌面、窄屏、Sheet 打开和图片导出时的署名。未有导出/离线授权的底图与照片，不因为会员设计或素材生产计划就默认可以永久保存或离线打包；交给相应采购与功能任务核对。

本轮不生成或上传地图截图、照片素材、Provider Token、真实个人位置或订单凭证。

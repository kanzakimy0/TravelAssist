# 已确认设计决策

> 本文件只记录已经可以作为开发依据的决策。讨论稿、候选方案和未确认想法不写入“已确认”。

## 2026-09-04

### 产品阶段

- [已确认] 先开发 Web 版本，再扩展手机 App。
- [已确认] App 尽量复用 Web 阶段形成的数据结构、业务逻辑与后端能力。

### 首页

- [已确认] 首页保持极简，不堆放大量宣传语。
- [已确认] 首页主入口为“让我们开始吧”。
- [已确认] 首页包含登录入口。
- [已确认] 右下角提供 AI 入口，可直接开始对话。
- [已确认] 整体视觉偏圆润、沉浸式。
- [已确认] 可以吸收 Komoot 的地图产品感与动态背景思路，但不直接复制。
- [已确认] 当前主视觉方案不使用绿色作为主色。
- [已确认] 可以加入适量日本元素，但最终表现方式仍待设计。

### 行程主页面

- [已确认] 桌面版核心页面以地图为主体。
- [已确认] 页面整体约为左 3 / 右 1 的视觉比例。
- [已确认] 右侧设置区域采用镶嵌 / 浮在地图内的表现方式。
- [已确认] 右侧上部为详细设置区域。
- [已确认] 右侧下部为推荐方案列表。
- [已确认] 推荐 1 显示更完整摘要；推荐 2、3 等默认更精简。
- [已确认] 页面底部设置连续行程时间轴。
- [已确认] 时间轴同时包含时间、景点、交通、餐饮等行程信息。
- [已确认] 地图中需要表达步行、电车、公交等交通方式。
- [已确认] 地图可以展示推荐住宿区域。
- [已确认] 地图可以展示推荐午餐 / 晚餐区域。
- [已确认] 景点使用地图标记，并可使用象征图片增强辨识度。

### 偏好系统

- [已确认] 偏好采用“大项目 → 中项目 → 小项目”三级结构。
- [已确认] 默认只展示少量关键内容，不一次展开全部详细设置。
- [已确认] 中项目提供快速设置。
- [已确认] 小项目用于高级详细设置。
- [已确认] 同行人设置应放在较前位置。
- [已确认] 当前同行人讨论至少包含成人男性、成人女性、小孩、婴儿。
- [已确认] 系统可利用同行人组合辅助判断亲子、情侣、家庭、朋友等旅行倾向，但不能覆盖用户明确偏好。
- [已确认] 移动偏好包含少换乘、少步行等方向。
- [已确认] 已讨论的小项包含不乘坐公共交通、不乘坐公交、不乘坐游船。
- [已确认] 景点与活动偏好不能只停留在大类，需要支持拍照等更细行为偏好。

### AI

- [已确认] AI 是全局交互入口，不是孤立聊天页。
- [已确认] AI 能把自然语言转换为结构化旅行条件和偏好。
- [已确认] AI 生成多个候选行程方案。
- [已确认] AI 可以根据后续自然语言修改行程。
- [已确认] AI、地图、时间轴、设置面板需要共享同一份结构化 Trip / Preference State。
- [已确认] 已经获取且仍有效的信息不应重复询问。

### 开发协作

- [已确认] GitHub 作为正式开发与协作入口。
- [已确认] `main` 保存稳定 / 发布版本。
- [已确认] `develop` 用作日常集成分支。
- [已确认] 功能开发使用 `feature/*`，Bug 使用 `fix/*`。
- [已确认] A 约承担 70%，B 约承担 30%。
- [已确认] A 主要负责核心架构、关键功能、集成和发布。
- [已确认] B 主要负责可独立拆分的页面、组件、测试、数据整理与临时接手任务。
- [已确认] 正式工作使用 GitHub Issue 记录，而不是只依赖聊天内容。
- [已确认] Codex 实现前必须阅读对应设计文档与 Issue，不自行补充未确认业务规则。

## 3. 图片来源与真实性边界

六项均为本会话此前生成的 AI 图片，本轮没有重新生成。生成标识、源文件名、原始尺寸、文件字节数和 SHA-256 / Git blob SHA-1 均记录在 manifest。

“写实”描述的是风格，不代表现场实拍、实际季节、当前天气或地点细节已核实。可作演示与氛围素材；不得用作酒店实景、预订凭证或真实行程证据。概念图中的樱花与示例旅行日期不能被当作真实花期承诺。

`avatar-yuki.webp` 是虚构演示头像，不是用户本人照片。仅用于明确的演示账户；真实用户应读取自己的头像或默认占位，不应批量替换为该肖像。

鸟居标志为本轮生成的 **RGBA PNG 候选素材**，不是 SVG，也不代表全站品牌审批完成。不得将扩展名改为 `.svg` 冒充矢量文件。此次不覆盖其他 identity 分支中的图标。

## 4. 已完成的本地处理

源图以英文稳定文件名原样复制归档；原始图片字节不变。五张照片经过 EXIF 朝向规范化、Lanczos 重采样与极轻微中心裁切，输出为 WebP，`quality=88`、`method=6`。Hero 为 1920×800，三张旅行卡为 1200×720，头像为 512×512。

Logo 原始 RGBA PNG 原样复制，保留 2172×724 与透明通道，没有描摹、换字或加底色。完整原图均保留在交付包中。

**不再做额外的 -10% 饱和度 / 对比度处理**：此前生成图已按用户认可的低饱和、温暖写实方向制作，不能在导出和 CSS 中重复叠加全局降色。背景和照片可局部微调，但须另做截图验收。

所有十二个图片文件（六原图 + 六网页版）均可被 Pillow 解码，尺寸已核对，哈希已计算。这是本地文件完整性验证，不是浏览器视觉验收，也不是远端验证。

## 5. 各图的实装处理依据

### 京都 Hero

使用 `/media/personal-center/hero-kyoto-sakura.webp`。照片作为底层，左侧通过暖米白渐变为深色文字提供可读区域；目标是左侧文字清楚、右侧街景和塔仍可见，而不是整幅图片覆盖白膜。

建议初始 `object-fit: cover`，`object-position: 65% 50%`；按真实容器调整，不能机械按源图比例固定桌面高度。目的地、日期、同行人数、交通标签和“查看行程”按钮均由组件渲染，不写进图片。

### 三张旅行卡

京都、大阪、北海道各使用独立封面。保持三等宽卡，采用全图背景、底部局部暗渐变、白色标题和元信息；不再使用“上半照片 + 下半白色信息板”。卡片状态与右下圆形箭头由代码实现。

裁切起点：京都 `60% 50%`；大阪 `65% 45%`；北海道 `50% 55%`。这些是调试起点，不是已完成的浏览器验收数据。照片不拉伸；小屏使用独立适配，不把整页压成截图。

### 演示头像与标志

Sidebar 与右上演示头像共用 `avatar-yuki.webp`，圆形裁切通过 CSS，起始位置 `50% 40%`，圆环不烘焙进图片。

Logo 使用 `object-fit: contain` 保持完整字标；透明背景不替换成黑底。若需单独的小鸟居导航标记，后续提供真正的矢量组件，不强行缩小整张横向字标。

## 8. 上传后回读验证清单

回读实际目标分支，不仅查看上传工具返回的成功提示。至少验证：

1. 六个 `runtime_path` 与六个 `source_path` 均存在，类型为真实二进制图片，不是路径字符串、Base64 文本或 LFS 指针。
2. 文件大小与 manifest 一致；Git blob SHA-1 与预期一致。可下载时，再算 SHA-256、解码并核对尺寸。
3. 校验本 Markdown 与 JSON manifest 均存在，记录实际提交 SHA；在素材分支成功不等于已经进入 `develop`。
4. 两个既有 SVG、其他 Task、WBS、页面代码不被覆盖；目录差异只包含授权交付文件。
5. 不把本次读回验证写成 build、测试或网页视觉通过。
